## Reviewed Design Spec

Round 22 confirms the complete revised symmetric standard-workspace behavior: one adaptive desktop-capability layout, exact `docked | strip` effective outputs for both sides, consuming/overlay strip behavior, explicit hybrid strip actions, origin/personal visual continuity, and mutually exclusive side rendering. A fitting wide user-origin strip emits `redock-panel` and restores the full panel/visible preference; constrained, narrow, or responsive-yield strips emit `open-drawer`, preserve stored preference, and hide that side's strip for the duration of the transient drawer. Dismissal re-evaluates the current policy state and restores the strip or docked panel without preference mutation. Drawer open/closed state remains local transient interaction state and is not a policy presentation. No leading hamburger/breadcrumb, visible drawer title, separate close X, duplicate panel toggle, or simultaneous strip-plus-drawer state is allowed. The wide default and manual-collapse states preserve the personal-branch left navigation/history + center Work + right tool hierarchy without a generic top-level row; `/mobile` remains separate. `layouts/default.vue` has an explicit route-scoped boundary: `/workspace` ignores `showHeader` for workspace-only suppression, other default-layout routes retain the shared compatibility behavior, and `/mobile` remains `layout:false`. The route gate is render-only and does not create a second responsive policy owner. The requirements, design, workspace UX, and right-tool UX artifacts consistently qualify strip visibility as drawer-closed and state that the opened drawer is the sole visible surface for that side. `LID-003` remains bounded implementation work against this approved contract.

The right-tool header remains one row with preserved visuals and uses horizontal scrolling, conditional edge affordances, active/focused-tab auto-scroll, and a stable panel-toggle action in docked and transient drawer containers. The guaranteed consuming/overlay-strip, hybrid activation, DI-010 schema, personal-branch strip/chrome contract, and mutual-exclusion renderer contract are clear in the core design and supplements. Strip visibility is consistently scoped to drawer-closed state, while an open transient drawer is the sole visible surface for that side. Current source drift is bounded to suppressing each side's strip while its local transient drawer is open; the prior extra visual controls are removed, and `CR-015` is resolved in the current source.
