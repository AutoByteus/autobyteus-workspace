## 2. Before either kind of tag (UC-004)
Both beta and stable, including --no-push/prepare alias, invoke one read-only verifier after preliminary version/repo checks and before ANY release-tree mutation. Use scripts/desktop-package/check-release-trust.mjs or equivalently named single owner. Share the strict public state reader and environment policy contract with setup; no dependency installation, private material, workflow dispatch, or trusted local backup to run this check. Status/manual dispatch are not tag creators. Keep signer-side equality check; preflight is a snapshot, not an authorization to skip it.
- On official GitHub repo validate current Ed25519 public anchor, exact environment restriction, secret name + metadata only there, no broader duplicate, unexpected override or setup-in-progress. Distinguish missing/misconfigured from inability to inspect. Then require a **positive signing witness for the current secret generation**: previous official desktop release at an immutable checked tag SHA, matching official tagged Desktop Release run/attempt and successful sign-linux-desktop job with its expected sign-and-verify step. Current secret and environment creation/update (secret created_at AND updated_at; environment creation for identity) must strictly predate signer job start, not merely precede job end; equal/ambiguous timestamps refuse. Verify both bounded public release records/signatures for that exact tag and x64/arm64 under TODAY’s public key using existing release-record verifier, including product/version/channel/target. Validate asset provenance (canonical names on official tag only) and that the run/attempt's signing code enforces the existing environment/secret + private/public equality contract (pinned reviewed signer and relevant workflow step, not arbitrary job title). No large binaries downloaded or executed, no secret exported. A valid signature alone from an older key generation or an unrelated run is insufficient. A wrong public key/signature, changed secret, re-created env, failed/missing run, unknown API/permission, or unverifiable witness fails closed. Use official bounded API reads, pagination/explicit run ID for a superseded release within a bounded search; an explicit witness ID selects evidence, never skips verification. Show which state to inspect, not secret contents. A failed unrelated newer run does not invalidate a still-current witness.
- **Bootstrap:** beta.2 tag already exists; M1 permits Mac owner to rerun its failed jobs independently of this work. A successful protected signing run with official release sidecars can be the first reusable witness. Until one exists the new preflight deliberately says “production signing not yet proven for this key; no tag created.” Do not tag locally to bootstrap, add branch exceptions, read GH secret, or silently accept local pair proof as remote signing proof. Mac's existing release decision remains theirs. If that owner cannot establish the first witness, escalate immediately for a separate decision on safe bootstrap, without weakening the gate or blocking M1. No production pipeline success unless Mac supplies actual evidence. Further tag preflights stay fully automatic with valid witness. No guarantee against malicious repository admin or an edit after the check.
- This favors existing trusted job evidence over a new privileged workflow. If actual GitHub run data cannot identify the signed generation/steps unambiguously, stop for design recovery. No new signing oracle or fixed stale fingerprint file.
