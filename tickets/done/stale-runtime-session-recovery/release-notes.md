## An older run continues when its agent runtime has lost the saved session

- Before, a run you came back to after a long pause could be stuck: Claude Code deletes the sessions it saved after 30 days, and every message to such a run failed with `CLAUDE_PROCESS_EXITED: No conversation found with session ID …`, although AutoByteus still held the whole conversation and the work journal. Now the message is answered. The run continues in a new session of the same agent runtime and model; the chat shows one line, "The saved Claude Agent SDK session of this run was no longer available, so a new session continues from the work journal.", and the new agent first gets the hand-over notice that points it to the earlier work journal, as after a runtime switch. Everything earlier stays in the chat.
- It works on every agent runtime that keeps a saved session (Claude Agent SDK, Codex App Server, Antigravity CLI, Grok Build and DeepSeek Harness), for standalone runs, Team and Org members, delegated copies, and runs started by applications.
- The new session has the journal, not the old session's own memory: its tool state and cache are gone, as they are after a runtime switch.
- Only the runtime's own answer that the session does not exist starts a new session. A sign-in problem, a network error or any other failure still fails as before and keeps the saved session, so the next message tries again.
- A Claude run restored from a saved session now starts its Claude Code process when the run is restored (about a quarter of a second), instead of at its first message. A restore that fails for another reason now shows that failure when the run is restored rather than in its first turn, with the same error.
- AutoByteus does not change how long Claude Code keeps its saved sessions; that is your choice in Claude Code's own settings.
