## Delivery Summary

- Delivered scope:
  - **A run whose runtime has lost its saved session continues instead of failing every message.** When the runtime itself reports that the run's saved session does not exist, the run continues at activation in a fresh session of the same runtime and model. The earlier records become one closed `runtime_switch` segment, the lost-session marker starts the new file, the work journal's hand-over notice goes with the input, and the commit replaces the lost session ID. The chat and journal show one line: "The saved <runtime> session of this run was no longer available, so a new session continues from the work journal." One `RUNTIME_SESSION_LOST` warning names the run, the runtime and the lost ID.
  - **Why it happened.** Claude Code deletes saved sessions after 30 days (`cleanupPeriodDays`, unset in the founder's settings). The founder's `architecture_reviewer` (a Team member, last answered 2026-10-14) was messaged 36 days later; `--resume` failed before any input, on every message, although AutoByteus still held the traces and the journal. The same dead end existed on every external runtime, each with its own signal.
  - **Exact recognition per runtime, one typed error (`SavedRuntimeSessionMissingError`), thrown by the backend that knows the answer.** Codex `no rollout found for thread id <id>`; Antigravity's stderr warning `conversation "<id>" not found` followed by a new conversation (any other mismatch stays `AGY_CONVERSATION_ID_CONFLICT`); Grok `FS_NOT_FOUND`; DeepSeek Harness `-32602 session is not resumable: <id>`; Claude, which used to open its process only at the first input, now opens a restored session's process at activation and awaits the SDK's initialization (`verifyResumable`), where the CLI's own error result and exit come before any turn exists. Any other failure (sign-in, network, a broken CLI, a quarantined cleanup, an unconfirmed release, a lifecycle without the switch port) fails as before and writes nothing.
  - **One owner per activation path, sharing the switch's steps.** Standalone runs and delegated copies: `StandaloneAgentRunLifecycleService` (`renewLostSession` → `activateInFreshSession`, key `session_renewal:<runId>:<lost ID>` so a retry finds its own marker and segment). Team and Org members: `ConfiguredAgentExecutionHandle` / `ConfiguredAgentActivationPlanner.beginSessionRenewal`, committed as `replace_lost_session`, a compare-and-set of the lost ID in the root's tree, handled by all five consumers of the change union (design Case 26).
  - **Every composition gives a renewal both parts** (SR-003, DEC-007, design Case 27): the switch memory and the hand-over notice first in the run manager's input preface. The studio already had both; the application execution scope now has them (the notice as its only platform notice), and so does the standalone application host (its standalone runs, delegated copies and members). No path renews without the notice and none keeps the dead end.
  - **Behavior changes carried into the release notes:** a restored Claude run opens its CLI process at activation (about 0.26 s); a restore that fails initialization for another reason now fails at activation, not in the first turn, with the same error.
- Docs synced (`docs-sync-report.md`): the implementation updated `GLOSSARY.md`, `agent_execution.md` and `run_history.md`; the Solution Designer added design Cases 26 and 27; delivery corrected five more places that said something now untrue (the Claude "lazy open" and the platform-notice composition in `agent_execution.md`; the "resume error is terminal" statements in `codex_integration.md`, `grok_build_runtime.md` and `antigravity_cli_runtime.md`; the DeepSeek restore line). `DESIGN.md` and `RELEASE.md` need no change; `TESTING.md` lacks Claude's test-home method (FU-003, API/E2E's document).
- Durable coverage: unit tests of each recognition on the real error shapes with negative controls (`IMP-03`: NC-01…NC-16 each fail); `standalone-session-renewal`, `member-session-renewal` (real Team and Org roots, the delegated copy, the compare-and-set, retries), `runtime-switch-session-renewal` (the real switch memory), one wiring test per composition (`application-scope-session-renewal`, `host-session-renewal-wiring`, the kernel builder; IMP-12 negative controls); the built-server E2E `lost-session-renewal-built-server` (scripted Antigravity: LS-01 standalone with restart, LS-02 Team member, LS-03 a conflict that is not a lost session); and the gated live file `lost-session-renewal-live.e2e.test.ts` (LC-01 real Claude, LC-02 busy restart, LC-03 real Codex) with its recorder guard.
