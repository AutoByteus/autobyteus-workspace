## Current Persisted Shape
`<appDataDir>/projects/<projectId>/project.json`, as established by store/layout contracts (not a live user sample):
```json
{"projectId":"project_…","name":"Example","description":"","createdAt":"…","updatedAt":"…","workspaces":[{"workspaceId":"agent_ws_…","workspaceRootPath":"/absolute/project/root","description":"Source code","addedAt":"…"}]}
```
Link descriptions are already optional in tool input and stored as strings. `addedAt` is existing metadata, not an argument the user needs. Workspaces remain a list, not a single top-level path. Project identity is not the workspace identity.

## Supported Paths / Root Cause
BEH-001/SCN-001: selected tool create/patch -> manifest -> ProjectService record command -> exact JSON writer. BEH-002/SCN-003: store -> view enrichment -> GraphQL/feed -> UI. BEH-003/SCN-002: omission-preserving patch and full list replacement inside catalog lock. IDs are an existing end-to-end membership contract, not just an incorrectly labelled tool parameter. A path-to-ID adapter alone would improve input but would not satisfy path-authoritative persisted links; simply removing the ID from JSON without changing the reader would drop links.

Existing ProjectService/store/tool/API/UI owners can absorb a bounded coordinated model correction; no new subsystem, generic path registry, compatibility adapter or background cleanup needed. Removal of ID and link timestamp affects all Project transports and supports Medium/High classification once design is complete.
