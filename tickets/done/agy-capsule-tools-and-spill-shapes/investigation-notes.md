| F-05 | **The capsule's `tools:` list is an allowlist that works:** `AGY_NATIVE_TOOL_NAMES` is written into the agent.md of every Antigravity run (`agy-run-capsule.ts:53`). With the current list the agent's reported tools were exactly `run_command, manage_task, read_file, write_file, edit_file, generate_image`; with only `read_file`: `read_file, manage_task`; with no `tools` key a different default set without `run_command` and with `search_web`, `schedule`, `send_message`. | F-06 | **CORRECTION (SR-002): the existing names are the CLI's own tool names; the "current" names are model-facing aliases.** The CLI's start message (\`init.tools\`, 60 names) lists \`view_file, write_to_file, replace_file_content, grep_search, list_dir, find_by_name, run_command, generate_image\` (all eight of our names) and does **not** list \`read_file\`, \`write_file\`, \`edit_file\`: those are what the model is shown for \`view_file\`, \`write_to_file\`, \`replace_file_content\`. So the list was never stale. SR-001's reading ("stale, works through an alias") came from the model's own answer, which shows the aliases, and from not checking the registry. | **Reproduced** (probe: \`init.tools\` of a capsule started with the existing list; all eight true, the three aliases false). |
| F-07 | **Mixing the two spellings fails:** a list with both a canonical name and its alias (\`read_file\` with \`view_file\`, \`write_file\` with \`write_to_file\`, \`edit_file\` with \`replace_file_content\`) makes the CLI refuse to start: \`failed to construct executor: tool name conflict: multiple tools resolved with name "read_file"\`. The alias-only list of five works. \`grep_search\`, \`list_dir\`, \`find_by_name\` are accepted but the model is not shown them on 1.5.15. An unknown name is ignored. | Reproduced by the implementation engineer (IMP-03 log) and by my probes. |

| F-10 | The tools the model sees on 1.5.15 with the existing list: \`read_file, write_file, edit_file, run_command, generate_image\` and the CLI's own \`manage_task\`; \`grep_search\`, \`list_dir\`, \`find_by_name\` are in the allowlist and the registry but are not shown to the model (it searches with \`run_command\`): a CLI/model decision, not ours. | Reproduced. |
