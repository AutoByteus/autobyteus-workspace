## Delivery Summary

- Delivered scope:
  - **A reference file opens in every view that lists it.** The founder's case: in the Messages tab of a delegated task team member, clicking a message's reference file showed "Reference file unavailable". Root cause (`root-cause-report.md`): the page listed messages from the view's composition (the root's log plus the logs of the runs it delegated to), but each of three REST routes read only one run's log, and three hand-written web links built the URL from a different identity. A message stored in a delegated run's log was listed and could not be opened. The same fact (which messages a view holds) was derived in four places, and the autobyteus-461 refactor updated one of them (design Case 28).
  - **One server reader and one route.** `RunViewMessagesReader` is the one reader of "the messages of the view of run X"; the participant page and `MessageReferenceContentReader` both read through it. The reference reader finds the message in the view, then the reference by the one ID rule (`messageReferenceId`), then the file, and serves only a path that a message of that view names (QR-001). One route serves every root kind: `GET /rest/collaboration-messages/:rootKind/:rootRunId/messages/:messageId/references/:referenceId/content` (`rootKind` `agent`, `agent_team` or `agent_org`). Removed: the three old routes, `TeamCommunicationContentService`, `AgentOrgReferenceContentService`, `resolveReference` and `projectMessage`.
  - **One link builder on the web.** `messageReferenceContentPath` builds the link from the key that loaded the list (`participantMessageRows.ts`); the three hand-written links and the `test-support` copy are gone, and the phone's authorized fetch covers the new prefix.
  - **The viewer says why.** A 404 with code `REFERENCE_NOT_FOUND` shows "This file's message could not be found in this conversation."; `REFERENCE_CONTENT_UNAVAILABLE` keeps "The file may have been deleted, moved, or become unreadable." (en and zh-CN). Context files open as before.
  - **The class of bug is guarded.** The permanent built-server E2E `message-references-every-view.e2e.test.ts` (MRV-1) builds standalone, Team and Org roots, each with a delegated task team and a delegated task agent, with cross-run messages and messages inside the delegated runs, and asserts that every reference listed in every view (each root's own tab and each delegated run's member tab) answers 200 with the file's bytes through the web's link form. `TESTING.md`'s "Choosing the path" has a new row for any change that moves where data lives (AC-008): every read path, every owner kind, asserted as a property; an old-place copy does not count; "expected to work" is a gap.
- Docs synced (`docs-sync-report.md`): delivery corrected eight long-lived docs that named the removed routes or the deleted files (the six the code reviewer listed, plus the server `agent_artifacts.md` and the web `remote_access.md`). `TESTING.md` was written by API/E2E; `docs/design-cases.md` Case 28 by the Solution Designer. `DESIGN.md` and `RELEASE.md` need no change.

## Residual Risks For The User

- R-1 (held by the code reviewer, `CRR-001`): a view whose records cannot be read now answers 500 on the reference route; the old standalone route answered 404 for that (the Team and Org routes already answered 500). No supported scenario reaches it: a reference link exists only in a list that the same reader already loaded, and a view that later becomes unreadable (a deleted or broken run) fails its participant page the same way. Not promoted; if a "run deleted while its tab is open" scenario is ever supported, the owner is `RunRecordsSource` with a typed not-found error for every kind.
- R-2 (not run): the packaged Electron app (its renderer fetches the link the same way as the browser the probe used; the desktop shell has no own path for it) and a real-runtime Team or Org run (the runs are created by the scripted Antigravity CLI; the reading is of real logs and files).

- R-4 (app and node versions): the link the app uses changed and the old routes are gone, so an app and a node of different versions cannot open each other's message reference files. The release notes ask users to update both together.
- R-5 (host): the whole unit suite fails `SR-016` on a Mac whose `TMPDIR` is not canonical, whatever the branch (FU-002).
