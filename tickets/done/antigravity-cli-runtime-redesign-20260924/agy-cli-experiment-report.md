# AGY CLI capability experiments — 2026-09-24

## Scope and interpretation

This is **investigation evidence**, not an approved product or architecture design. I tested the locally authenticated `agy` **1.2.10** binary (the machine had reported 1.2.9 earlier the same day) with `gemini-3.8-flash-low`, temporary project folders, and short prompts. No global settings were edited. Initial probes did not use `--dangerously-skip-permissions`; the later SR-008 auto-approve control deliberately used it with a harmless command and `--sandbox`. Probe scripts and sanitized JSON outputs in this directory make the observations traceable. These are bounded samples on one machine/version, not cross-version guarantees or proof of prompt-injection resistance. AGY may retain test conversations in its own normal history/cache even though temporary workspace files were removed.

**SR-015 raw-stream supplement:** The user's request for the actual JSON emitted during tool calls is answered by `agy-tool-event-capture-analysis.md` and verbatim stdout/stderr files in `agy-tool-event-capture/` (read, allowed/denied/nonzero command, file write, and two-turn tool stream). The earlier summaries below did **not** store full provider stdout; the new supplement does. It also identifies a new limit: an executed command exiting 7 was reported as tool DONE without machine-readable exit status in that sample. Do not confuse this probe-only raw evidence archive with a proposed production AGY NDJSON archive; production direction remains normalization into AutoByteus raw traces.

Official contract references: [custom main agents](https://antigravity.google/blog/introducing-custom-agents), [Projects](https://www.antigravity.google/docs/projects?tab=cli), [headless streaming and permissions](https://antigravity.google/docs/cli/headless/), [agents and switching](https://www.antigravity.google/docs/cli/commands/agents), [hooks](https://www.antigravity.google/docs/hooks), [exact resume](https://antigravity.google/docs/cli/commands/resume), [workspace rules and MCP locations](https://antigravity.google/docs/cli/gcli-migration/).

No Git repository was needed for the successful new-project test. | Current CLI supports **real system-level identity** through a custom main agent, but project initialization/discovery is critical. `init.agent` is not validation that the file loaded. |
| First user message as identity | One stream sends a user instruction to remember `FIRST-EMBER`, then asks for it. The old workaround is inferior and misses direct PTY input. |
| Custom agent versus conflicting user instruction | Custom main-agent system body assigns `SYSTEM-CYAN`; user asks to override it with `USER-RED`. | One short turn answered `SYSTEM-CYAN`. | Supports using the custom-agent system surface. | Agent selection validation | `--agent nonexistent-name` and a missing/undiscovered local agent; `agy agents` in tested temporary folders. | The CLI did not reliably fail on unknown selection; live response fell back to default, while `init.agent` could echo the requested name. `agy agents` produced no useful listing in this environment. | Validate generated agent assets and startup contract; do not treat accepted flags, `init.agent`, or `agy agents` output alone as proof that run identity is active. |
| Multi-turn streaming | `--input-format stream-json --output-format stream-json`, two NDJSON user messages. | `init` supplied a CLI-generated `conversation_id` before first user turn; each turn supplied `result`, same ID, cumulative `num_turns`. | A structured-chat adapter can bind provider ID early and model actual turn completion without screen scraping. Counter fields are cumulative, not per-turn. |
| Exact resume | New process with `--conversation <captured-ID>` after the two-turn stream. | Same ID and remembered nonce; cumulative turn count became three. | CLI ID is an external binding separate from AutoByteus run ID; no caller-created conversation ID is required. |
| Invalid exact resume | New process with random nonexistent `--conversation` ID. | CLI exited **0**, wrote a warning to stderr, and emitted a *different new* ID in `init`. | **Critical:** `--conversation` is not fail-closed. | Identity across resume | Start custom agent with `IDENTITY-ALPHA`, resume, edit the agent file to `IDENTITY-BETA`, resume again. | Same CLI ID recalled an earlier user nonce and answered `IDENTITY-ALPHA` after the file edit. | In this case the existing conversation retained its original identity. | Run-local hook | `.agents/hooks.json` in generated primary folder, `PreInvocation` command captures payload; compare with/without `--new-project`. | With new project, hook fired twice and its `conversationId` matched structured `init`; without new project it did not fire. | Useful independent ID channel for **tool invocations**, but cannot guarantee capture before any first prompt or in no-tool conversations. |
| TUI and log timing | Sized 40×120 PTY; `--new-project` custom agent; `--log-file`; idle TUI with no prompt, then a separate `--prompt-interactive` sample. | Idle TUI produced bytes and a log file, but **no** `Created conversation` line within ~6 s. The prompted sample displayed custom-agent name and produced one `Created conversation` line with an ID, but did **not** visibly return the expected model code within ~36 s. An earlier ad hoc PTY turn did show the code. | TUI startup alone does not furnish a demonstrated conversation binding. The model-response result is mixed/inconclusive, and a PTY route needs a reliable post-creation capture/reconciliation contract. Do not parse screen text as authoritative conversation state. |
| Headless permission behavior | Harmless `printf PERMISSION-PROBE` request, default `request-review`, no bypass flag. | `run_command` tool step entered `ERROR`/denied; overall `result.status` was `SUCCESS` with empty response, process exit **0**, stderr explained soft denial. | A structured adapter must surface tool-denial diagnostics; process exit and result status alone are insufficient. | Headless auto-approve control (SR-008) | Harmless `printf AUTOAPPROVE-PROBE` in a disposable new-project folder, `--sandbox --dangerously-skip-permissions`; no real user workspace or global-settings edit. | `init.permission_mode` was `always-proceed`; `run_command` reached DONE with the exact marker output, overall SUCCESS, exit 0 and no denial. | For current AGY 1.2.10, its all-tools approval flag enables a structured headless shell tool. ## Current CLI surface and docs, not all independently exercised

- `agy --help` exposes `--new-project`, `--project`, `--agent`, `--conversation`, `--continue`, `--add-dir`, `--log-file`, PTY/interactive and headless stream modes. No caller-chosen **new** conversation ID flag was found. `agy models` listed Gemini, Claude, and GPT-OSS model slugs on this installation; availability is a dynamic local/account contract, not a stable hardcoded product list.
- The [Projects documentation](https://www.antigravity.google/docs/projects?tab=cli) explains the no-flag CLI's shared `default-cli-project`, `--new-project` creation, `--project` selection, and automatic associated-project selection on exact conversation resume. This explains the test's new-project dependency; it is an **inference** from docs plus behavior, not a trace of AGY internals. Project scoping/cleanup and project-ID exposure still need implementation-time tests.
- [Custom agents](https://antigravity.google/blog/introducing-custom-agents) explicitly say the Markdown body compiles into the system prompt for a main agent. This supersedes the old assumption that AGY cannot receive system-level per-agent identity.
- [Agent switching](https://www.antigravity.google/docs/cli/commands/agents) can fork a conversation; project `/fork` also changes its ID. Any supported in-session switching/forking must update provider binding, or be excluded/blocked by approved behavior.
- [Headless docs](https://antigravity.google/docs/cli/headless/) state stream protocol limitations: input requires output `stream-json`; `-p` prompts are dropped in streaming-input mode; slash commands can break the JSON flow; malformed/control input terminates session; unknown model in headless fails rather than silently falling back. These are docs contracts, not all independently retested.
- [Migration docs](https://antigravity.google/docs/cli/gcli-migration/) locate workspace MCP settings at `.agents/mcp_config.json` and rules at `AGENTS.md`/`GEMINI.md`. MCP loading, credentials, and permission behavior were not probed; generated configuration must not overwrite user-owned workspace files. No global settings were modified for this investigation.

## Conclusions for later solution design (non-authoritative)

1. **Use a run-local custom main agent rather than first-user-message identity.** The original AutoByteus `agent.md` body can often be reused, but generate/validate the AGY wrapper and compose the *full current AutoByteus identity* (including external team context) into its system body. This is supported by official docs, direct behavioral comparison, and one actual-file compatibility probe; still include startup validation because AGY can silently fall back when selection is wrong.
2. **Treat AGY Projects as part of run isolation.** In this environment `--new-project` was necessary for custom agent and hook discovery. Generated primary folder plus real workspace `--add-dir` worked, including a two-run no-write concurrency sample.
3. **Bind the CLI-created conversation ID, not a caller-invented ID.** Structured `init` is the strongest observed early channel. Exact resume works, but ID mismatch on missing conversation must fail closed. A TUI needs a later verified ID channel; hooks only fire on invocations, and log parsing is diagnostic rather than an ideal authority.
4. **UX/security remains unresolved.** Headless structured mode is the stronger match for the user's now-expressed interest in the existing chat frontend and persisted raw traces, but it silently soft-denies approval-requiring actions unless policy is arranged. Native TUI offers its own approval UI, but transport/state/ID capture is less clean. Also distinguish stored provider-event trace from a complete internal AGY trace: `view_file` returned only a size summary in the exposed stream. Neither choice can be made by technical convenience alone.

## Residual questions and bounded next validation

- User choice: native terminal versus structured chat; associated direct input, approvals, history, and startup semantics. For structured headless, explicitly confirm that existing per-run `autoExecuteTools=true` may use AGY's broad always-proceed flag, and decide how `false` behaves without interactive headless approvals; do not silently change defaults or user-global policy.
- User choice: whether old unmerged AGY runs require import, and whether an existing run must retain original agent identity after definition edits (the observed behavior) or be re-forked/restarted.
- If PTY chosen, validate a deterministic non-screen ID capture before restorable state, interactive approval handling, exact restore mismatch/fork detection, and a repeatable first-turn completion path. The 36-second PTY sample was inconclusive.
- If structured chat chosen, verify denial/error event interpretation, cancellation, model/agent drift, slash-command policy, stream crash/restart, and data persistence against the chosen UI contract.
- Verify generated project settings/MCP scope and real-workspace rule precedence, agent discovery on each supported OS/CLI version, write-concurrency effects, and project cleanup. These were not established by the bounded probes.
