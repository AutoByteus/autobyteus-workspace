## Direct answer: have we saved during migrations?
Yes: target writes, optional narrow backups, and runner audit records all exist. Some exceptional multi-file migrations retain source/provenance for a real retry boundary. Those are not a general precedent for a durable original/target hash+progress journal for every changed history file. Atomic-write temporary files are not backups; runtime layout manifests are not migration journals; SQLite rollback is not a custom backup protocol.
