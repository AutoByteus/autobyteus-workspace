## SR-003 — Explain existing runtime-default duplicate handling
User asks why Codex-default duplicates are notices and reiterates current behavior must stay unchanged. Additional exact sources inspected: src/skills/services/runtime-default-skill-folders.ts and src/skills/domain/installed-skill-record.ts (under autobyteus-server-ts), skill-catalog-one-per-name.test.ts, config/app-config.ts:getAdditionalSkillsDirs, and src/agent-execution/backends/codex/backend/codex-thread-bootstrapper.ts:planWorkspaceSkillRequests.
Findings: runtime-default directories enter the AutoByteus catalog only when configured as skill sources. Matcher uses realpath equality for CODEX_HOME/skills (or ~/.codex/skills), ~/.claude/skills, ~/.agents/skills, ~/.grok/skills. They have lowest precedence, regardless of settings order. A distinct custom/package/default copy with the same name wins; the runtime-default file is left untouched and ignored in the catalog. Duplicates among distinct non-runtime-default copies abort import; multiple paths to the same real skill folder are deduplicated, not treated as two copies. Codex native discovery is separately preflighted at run bootstrap: reuse native discovery only if every listed path for the name matches the chosen real folder; otherwise expose the chosen catalog skill in the workspace and log other paths. Native presence alone does not register ~/.codex/skills in AutoByteus's catalog. Tests inspected, not executed.
Rationale evidenced by code contract: runtime folders supply missing names as lower-priority fallback, not competing explicitly selected copies; this lets a user's chosen source take precedence without modifying their runtime's installation. No proposed behavior change.

### External source verification (2026-10-04)
- GitHub official repository and branch API docs: https://docs.github.com/en/rest/repos/repos#get-a-repository and https://docs.github.com/en/rest/branches/branches#get-a-branch establish metadata/default-branch and branch commit query surfaces; repository archive ref endpoint documented at https://docs.github.com/en/rest/repos/contents#download-a-repository-archive-tar . Use a resolved revision for the download, not a moving branch between check and extraction. No authentication requested for public imports.
- node-tar official README https://github.com/isaacs/node-tar documents strict extraction, filter and preservePaths=false protections. Library protections do not replace application source/path ownership checks.
- Maintainer advisory https://github.com/isaacs/node-tar/security/advisories/GHSA-gvwx-54wh-qm9j identifies a PAX NUL issue through 7.5.16, patched in 7.5.17. This is why the existing transitive 7.5.9 must not be reused. Release listing https://github.com/isaacs/node-tar/releases and npm metadata inspected; no claim all possible future vulnerabilities are excluded.

### Architecture investigation conclusions
No persisted-data conversion required: local source settings/disabled choices/agent registries keep their existing meanings and readers. GitHub skill source records are a new authoritative subject. Reference changes from generation roots affect skill workspaces and catalog paths, but not saved skill names. Latest checks must not create source registrations, replace files or overwrite newer source state. Missing/invalid new registry must never be silently overwritten as an empty writable registry; surface a skill-source error, keep unrelated local skills usable and do not create a startup-wide gate.

Remaining uncertainty is bounded implementation verification, not an unmade product choice: extraction/path platform behavior, workspace refresh boundary, transaction/failure tests and shared-client regression. Architecture review is needed for new persistence/API/security boundaries. No production code changed, no tests run, no live repository imported.
