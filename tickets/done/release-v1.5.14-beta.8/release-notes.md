## What you need to do

- **Update the app and every node you connect to together.** An app and a node of different versions cannot open each other's message reference files: the link the app uses changed, and the old one is gone. This applies to the desktop app, the phone app, paired desktop nodes and Docker or remote nodes.
- **Saved organization runs are converted on the first start, once, and this cannot be undone.** Nothing to do before upgrading: your saved organization runs keep their conversations, messages, memory, Tasks and history, and the files an organization's agent received from another node, or attached to messages and Tasks, still open from where they now are. After upgrading, do not install an older version; if you need to go back, contact support instead.
- **Paired nodes: upgrade both.** A node on an older version refuses the new team-membership update between nodes; the other node then catches up the next time it reads that team's status.
- **Docker nodes:** this release's server image is still system level 2, as the previous beta. A node that is still on a level-1 image (for example the stable 1.5.13) must be recreated once before it takes this beta: run `autobyteus-docker upgrade --all --tag beta`. A node already on the previous beta updates in place.
- **iPhone and iPad: update AutoByteus from TestFlight** to the new build, version 1.5.14 (build 354). It is a TestFlight beta only; nothing is sent for App Store review.
- **Desktop:** with **Settings > Updates > Receive beta updates** on, the app updates itself to this beta.

## What's new

- **Organizations are containers of runs.** Each team in an organization is now a team run of its own, and each organization agent an agent run of its own, with its own run, memory and messages. The organization still looks and works as one in the app (one launch page, one view, one Stop and reopen).
- **Teams inside an organization follow their team definition**, like any team run: adding or removing a member in the team definition updates the running organization's team (a busy member finishes its turn first), and the other members are told. Organizations follow their organization definition too: mounting a team or adding an agent adds it to the running organization (offline until first used); removing one lets it finish its work, then removes it, keeping its history. Organization handoff rules follow the members. On a paired node, the node that delegated work to a team on another node now sees the team's current members after the team changes.
- **Reference files of delegated agents and teams open from the Messages tab.** Before, a file in the tab of a delegated task team member, a delegated task agent, or a member of a task team inside an organization could show "Reference file unavailable". The root's own Messages tab also opens the files of messages between its agent and its delegated runs, and the phone's Messages screen opens them the same way. When a file cannot be opened, the viewer now says why: the node does not hold that message, or the file itself is gone or unreadable.
- **A tool call you stopped now says "Stopped"**, with a stop icon, in the conversation, in the Activity panel and on the phone, while the run is open and after you reopen it. It works for every agent runtime and for runs you stopped in earlier versions. Tasks of a stopped run end as "Stopped: the run ended" in the Background Tasks panel and on the phone's Activity.
- **Links in chat can point to a file in the run's folder.** A link such as `[clip](media/clip.mp4)` or `[notes](docs/a.md#intro)` that an agent writes opens that file from the agent's own folder, on the desktop and on the phone; nothing outside the folder is read.
- **The phone's Activity shows what each tool did.** A tool call shows the command it ran, the file it touched, the query, the recipient or the Task, and a clear status (a check mark for success; an icon and its word for any other state). Tap a call for its full details, which update while you watch. Memory compactions and background tasks open too. The desktop app uses the same wording.
- **Notices from the application get their own light row** in the conversation ("Application restarted", "Background tasks finished", "Skill updated", "Tools updated", "Agent runtime changed"), with an icon and a label, never inside the agent's message. On the phone the agent's name and picture appear again after a notice.
- **An older run continues when its agent runtime has lost the saved session.** Claude Code deletes saved sessions after 30 days; before, every message to such a run failed. Now the run continues in a new session of the same runtime and model, the chat shows one line saying so, and the new agent gets a hand-over notice that points to the earlier work journal. It works on every runtime that keeps a saved session, for single agents, team and organization members, delegated copies and application runs.
- **A file the node cannot give you shows an error message**, not raw text, in the Files viewer, the Memory page's semantic memory view, chat links and the phone's demo. A file whose own text is `{"error":…}` opens as the text it is.
- **Grok starts reliably and offers the right models.** AutoByteus waits up to 90 seconds for Grok to start on a busy computer (before: 15 to 30 seconds). After a few hours without Grok it now waits up to 3 seconds for Grok to announce its real model list, instead of offering Grok's older built-in models that a run then refused; reading the Grok model list and starting a Grok run take about 3 seconds longer. Grok agents also see the skills in their workspace, the same as Claude and Codex agents.
- Files open right after a node restart, the earlier-events page shows the same tool-card summary and "Stopped" status as the live conversation, and the Windows desktop build no longer leaves a staging folder inside the package.

## Good to know

- **A trusted run workspace can change how a Grok run behaves.** To show a workspace's skills, AutoByteus starts each Grok run with that run's workspace trusted, for that run only, and saves nothing in your Grok settings. As with trusted folders in Grok itself, Grok then also loads that workspace's own Grok hooks, MCP and LSP servers, instructions and permission rules.
- A DeepSeek agent that never starts now fails after 90 seconds instead of 15.
- A Claude run restored from a saved session now starts its Claude Code process when the run is restored, not at its first message; a restore that fails for another reason now shows that failure when the run is restored.
- A stopped tool call keeps the error text "Tool execution interrupted." in its details; a tool call that was interrupted shows "Unknown" on the phone, as it already did on the desktop. On the phone, a relative link inside a workspace Markdown file you open from Files still does not open the linked file.
- A new session after a lost saved session has the work journal, not the old session's own memory: its tool state and cache are gone, as after a runtime switch. AutoByteus does not change how long Claude Code keeps its saved sessions.
