## What you need to do

- **From v1.5.14: a normal update.** Nothing else to do. This beta adds no data conversion and no Docker system change (the server image is still system level 2, as in v1.5.14).
- **Phone apps: update them to get the new video and audio player.** On Android, install the APK of this release. On iPhone and iPad, update AutoByteus from TestFlight to the new build, version 1.5.15 (build @@IOS_BUILD@@); it is a TestFlight beta only, and nothing is sent for App Store review. The player starts only when the app **and** the node it connects to are on this beta; if either is older, files play in the page as before. Update your nodes too.
- **Docker nodes:** a node already on v1.5.14 updates in place. A node that is still on an older image (v1.5.13 or older) must be recreated once before it takes this beta: run `autobyteus-docker upgrade --all --tag beta`. The stable `:latest` image stays on v1.5.14.
- **Desktop:** with **Settings > Updates > Receive beta updates** on, the app updates itself to this beta.
- **Coming from v1.5.13 or older:** read the [v1.5.14 release notes](https://github.com/AutoByteus/autobyteus-workspace/releases/tag/v1.5.14) first. They have the steps that come with that release, among them the one-way conversion of saved organization runs on the first start, which cannot be undone, so do not install an older version afterwards.

## What's new since v1.5.14

- **Your running agents and teams stay running through a restart.** After an update, **Restart server**, `docker stop` and start, or a crash, the agent runs and teams you started come back running and idle, with their conversations: every one that was running when the node stopped. No message is sent to them and no model is called. Other agents can find them again with `list_running_agents` and message them; before, an idle run stayed unloaded after a restart, so other agents did not see it and started duplicate runs. This holds for a graceful restart and for a kill: after a crash the list of running runs is at most 2 seconds old. A run you archived or stopped stays that way. Runs that other agents delegated to, and Organizations, are not brought back by this: they come back when you open or message them, as before. If a run cannot come back (for example its runtime is missing), the server logs its name and the reason, the other runs still come back, and the server starts as usual.
- **Videos play at once in the phone apps.** In the Android and iOS apps, a video of your node opens in the phone's own video player. It no longer downloads the whole file before it plays: it starts in about a second, and a jump to the middle fetches only the part it needs. This holds for a video you open from Files, from a link in the chat, or from a media message. A wide video fills the screen in landscape, and leaving full screen returns to portrait at the same place in the video. On Android, the full-screen button of a video shown inside a page works too: it was disabled before.
- **Audio plays in the phone apps' own player.** An MP3, M4A, AAC or WAV file of your node (also AIFF and CAF on iPhone, FLAC, Ogg and Opus on Android) opens in the phone's player with the file's name and the standard controls. It starts in about a second and jumps anywhere by fetching only the part it needs, also over a slow connection. A type the app's player does not play (for example Ogg audio or WebM video on iPhone) keeps playing in the page, as before.
- **A file you reopen is not downloaded again.** The apps keep the parts they already fetched, up to 500 MB, and drop the least recently used first. When the file has changed on the node, you get the new version. Removing a node from the app empties its saved files.
- **A video or audio file attached to a Team or Organization message streams.** In the Messages panel on the desktop it starts at once and seeks, instead of downloading the whole file first; in the phone apps it plays in the app's player. Text, PDF and image attachments open as before, and an attachment that was deleted still says so.
- **The sound is heard on an iPhone set to silent.** The video or audio you tap plays with its sound whatever the Ring/Silent switch says, as in media apps, and other apps' audio resumes when you close the player. It does not keep playing after the screen locks.
- **A rewritten file shows its new content.** When an agent rewrites a file, opening it again shows the new version, in the phone apps, in the desktop app and in a browser. The node now tells every client to check for a newer copy before it reuses one.
- **Text and code files wrap in the file viewer.** Text and code files now open with word wrap on, on the phone and on the desktop: a long line wraps at the editor's width instead of running past its edge, so a workspace config, a JSON file or a draft written as one long paragraph reads without sideways scrolling. A wrapped line keeps the indentation of its line, and line numbers stay one per line. Editing, saving and highlighting work as before. This applies wherever the app shows a text file in its editor: the Files tab, the phone's Files screen, and the viewers for message references and artifacts. To turn wrap off for the file you are reading, use the editor's right-click menu, "Toggle Word Wrap"; the choice is not remembered for the next file.
- **The desktop file viewer is never too narrow.** In the Files tab, the viewer keeps at least 400 px beside the tree: when the panel is too narrow for both, the tree sits above the viewer, and dragging the divider stops at 400 px.
- **More file types are highlighted.** YAML, TOML, shell scripts, Go, Rust, Java, XML, INI files and Dockerfiles, and HTML and Vue files, are colored in the file viewer. In a chat message, a code block marked `yaml`, `toml`, `bash`, `sh`, `zsh`, `go`, `rust`, `java`, `xml`, `ini` or `dockerfile` is colored too.
- **Your phone's key stays private while a file streams.** It goes only to your own node, in a request header. It is never part of a link, a log or a saved file.

## Good to know

- The new player needs the new app and a node on this beta. An older app, the node's web page in a phone browser and the desktop app play videos and audio in the page as before.
- On iOS, the app's **Back** bar stays over a video in landscape and sits over the player's own top buttons while the controls show. Both close the player; swiping down does not.
- On Android, if the system switches dark mode while a video plays, the player shows "This video could not be played." Press **Back**, then **Play**: the video continues from what the app saved.
- On a connection slower than the video itself, the iPhone plays at the speed of the connection, and the time bar can run a little ahead of the picture.
- An attachment file of zero bytes shows "Failed to fetch reference content (416)" instead of an empty player.
- A running run of an external runtime (Claude, Antigravity) holds a runtime process of about 270 to 330 MB. A node with many such runs uses that memory after a restart, as it did before the restart. The node brings runs back three at a time. If you stop the node while it is still bringing runs back, the runs not yet handled stay on the list for the next start.
