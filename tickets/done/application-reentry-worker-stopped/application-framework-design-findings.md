Report only. Nothing here is fixed by autobyteus-296 except where the last column says so. The user decides what becomes a Task (related: autobyteus-291, code health of the whole product). Method: read against `DESIGN.md` (rules 1–10, GLOSSARY.md, Principle 15), the 500-line limit, duplicated owners, docs vs code, and the lifecycle states with who may call whom. How each finding was established: **Read** (code/docs read), **Reproduced** (run), **Measured** (counted).

Scope surveyed: `autobyteus-application-sdk-contracts` (13 files, 1,859 lines), `-backend-sdk` (3 / 218), `-frontend-sdk` (18 / 1,872), `-devkit` (32 / 2,401), and the server's `application-orchestration` (30 / 4,546), `application-platform` (29 / 4,569), `application-engine` (18 / 2,685), `application-bundles`, `application-packages`, `application-storage`, `application-backend-api-gateway`, `application-agent-tools`, `application-agent-communication`, `application-agent-streaming`, `application-capability`, `standalone-application-host` (Measured, `find … | xargs wc -l`). The SDK packages were surveyed for size, naming and versions only; the lifecycle and ownership review went deepest in the server's orchestration/platform code, where the bug is.

## Lifecycle: who may call whom

| State | Meaning (docs) | Admitted | Refused |
| --- | --- | --- | --- |
| `ACTIVE` | Serves backend and orchestration traffic | Backend gateway (`application-backend-api-gateway-service.ts:91`), host calls from the worker (`application-orchestration-host-service.ts:129-131`, 16 call sites), application tools (`application-agent-tool-gateway.ts:34`), agent-target authorization (`application-agent-target-authorization-service.ts:157`), event dispatch (`application-execution-event-dispatch-service.ts:86,122,140,194,210,224`) | — |
| `REENTERING` | One application is being resumed | Platform-internal recovery only | Every entrypoint above, including the application's own worker (`application-availability-service.ts:209-215`) |
| `QUARANTINED` | Diagnostics, setup required, or persisted-only | Repair (`POST …/backend/reload`), package commands | Every entrypoint above |

The rule is consistent: everything an application or a user drives needs `ACTIVE`. Findings 1 and 2 are where the code broke it.
