# DS-003 managed stage lifetime — implementation clarification
REQ-005/007, AC-006/008. “Expiring” describes validity of the one outstanding writer transaction, not elapsed time since download. A current verified stage survives an arbitrarily long uninterrupted session. Remove the one-hour deadline on a completed stage. Keep bounded socket/I/O deadlines for incomplete requests. No heartbeat, periodic refresh, new persistence, permanent grant or changed quit behavior.

Writer: the opaque receipt is single-use and expires on consumption, discard, supersession, writer restart/store reset, or change of its committed baseline. One bounded staged file per installation; discard/reap orphan on the existing replacement/startup paths. App session generation, opt-in and channel checks remain mandatory before dispatch. Receipt age alone never authorizes or refuses activation. Still reverify live/candidate identities, owner and signed release admission under the writer lock on activation. Never use a stale receipt to adopt a different candidate.
Recovery: distinguish known-absent/superseded receipt with a narrow machine-readable response (e.g. STAGE_GONE), not a generic string match. A channel mismatch, invalid signature, wrong peer, corrupt store or unknown commit outcome is NOT this result. Reconcile status on ambiguous replies as already designed. If candidate already committed, recognize it; if stage gone and confirmed old baseline still live, clear “ready” and the matching provisional attempt marker, not unrelated history. No AUTO_FAILED version block or false success. A changed/unknown live identity must be reconciled separately, not assumed old. Never clear a prior independent permanent block for that version. Manual refusal remains observable, without changing automatic retry policy.
Do not download or re-stage during shutdown. On ordinary quit continue to exit without reopening. On next eligible normal check with opt-in still enabled the ordinary download/cache + writer staging path must be able to acquire a fresh receipt for that same release automatically, including cache hits. No new action or authentication from the user. Manual restart after confirmed stop follows existing safe old-image recovery, with an accurate retryable explanation. Definitive integrity/admission failures retain the reviewed refusal policy.
Regression checks: unchanged receipt still activates after >1h/day (no wall-clock sleep); discard/supersede/restart defeats old ID; status and receipt-loss notification survive relaunch on old version without a synthetic automatic failure; same release is eligible to stage anew; opt-out at quit suppresses activation/retry and tampering is still rejected. Does not supersede normal readiness cutoff or extend to native/portable updates.
