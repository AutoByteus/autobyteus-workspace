App's existing check/download/channel/opt-in → protected install client stages request → OS-managed writer verifies immutable staged bytes → readiness → coordinator defers automatic activation to the next independently requested ordinary quit → atomic activation → fixed-path unprivileged relaunch on explicit restart, or next ordinary launch after normal quit; report running version, not just download success. Manual updates share verification. Current app/embedded server version pairing stays intact. Do not automatically terminate ongoing work to hit an update timer.

Installation lock serializes activation for the installation. On commit failure keep old file runnable and follow current recovery. Existing appUpdateInstallAttempt and automatic failure logic keep one authority; do not leave electron-updater's independent autoInstallOnAppQuit active for managed installs. No success notification until verified transition.
12: ## Privilege and interface boundaries
13: - AR-001 selected crossing, no alternative implicit: user intentionally starts the official downloaded release (initial trust assumption). The normal-user launcher reads only its bundled standalone native provisioner, verifies the expected build-pinned digest, snapshots the checked bytes in a kernel-sealed read-only executable file, checks all write/grow/shrink/sealing locks and retains the same open descriptor until the one-shot authorized child has exited. No writable mapping, path supplied by caller, on-disk mutable extraction, FD reuse, or privileged shell/interpreter. Root code consists only of the bootstrap program and its statically embedded fixed service/profile/menu templates, writer binary and public key. No commands or resources from the unverified AppImage run as root. Use autobyteus-web/linux-install/cmd/{launcher,provision,writer}/main.go and internal/release/record.go. Build writer first, embed in provision, then pin completed provision digest in launcher before packing AppImage; no circular signature on the final AppImage.
14: - Ubuntu authorization: launcher explains the operation and exact helper path that the OS will display, then invokes system pkexec for the retained **parent's** read-only descriptor path, not a child-inherited descriptor. PKEXEC_UID is set by pkexec from the invoking real UID; provision requires effective UID zero and a valid nonzero local PKEXEC_UID, resolves account via OS, derives all destinations from that UID and fixed constants. No UID/path/env overrides. No generic auth exemption, retained grants, or custom password handling. In graphical sessions use Ubuntu's registered agent; on a real terminal without one use Ubuntu's ordinary separately registered pkttyagent tied to this launcher process, wait for readiness, then pkexec with internal agent disabled. A headless noninteractive process cannot enroll. The system dialog identifies the program by path and requested account, **not by verified publisher**. Authentication proves permission, not publisher identity. The launcher retains custody during the prompt without delegating mutable code or assuming a custom policy is already installed. Failed seal, unsupported execution, auth refusal/cancel or absence of suitable agent stops: no retries with weaker policy. SR-013 VM witnessed stock 24.04 polkit and normal one-shot password verification; 26.04 and graphical acceptance remain required.
15: - Provisioning resource custody/order: parent supplies only bounded signed record, signature and final AppImage bytes through stdin (OS auth agent uses independent session/tty); bootstrap stages in root-private storage, verifies pinned desktop key, record, length/digest, arch and requested release before committing anything. No input path dereference, archive extraction, user-controlled service files or network trust injection. Set installer directories, service identity and protected immutable service assets; initialize writer store with first verified inode+attrs; install inactive socket/service and exact AppArmor profile; load profile then enable socket; return committed only when all ready. Parent then writes its own user-menu entry (never write into HOME as root) and launches canonical executable as that UID. Subsequent launch completes missing menu entry idempotently if parent was interrupted. On setup failure reverse only objects created by this attempt; leave existing managed installations intact, disable created socket and unload created policy before removing its files. Refusal before authorization writes no host state. Uninstall uses root-owned installed provisioner and same Ubuntu prompt; disable socket, stop owned writer, unload owned profile, remove only verified owned files/identity if unused; caller removes owned menu entry. No profile/data deletion. No host changing operation was part of the design VM witness.

39: ## DS-002: authenticated identity and atomic commit (AR-003)
40: Single contract in linux-install/contract/desktop-release.md with shared positive/negative byte fixtures, Go reader internal/release/record.go; JS signer scripts/desktop-package/sign-release.mjs and CI validator consume same fixtures. Signed content example (digest illustrative):
41: {"format":1,"product":"autobyteus-personal-desktop","artifact":"AppImage","os":"linux","arch":"x64","version":"1.5.14-beta.1","channel":"beta","size":339972678,"sha256":"0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef","minWriter":1}
42: Signer emits compact UTF-8 JSON in shown order plus one LF. Detached .sig is standard base64 of 64-byte Ed25519 signature over exact manifest bytes, no newline. Bounded <=4 KiB manifest, reject duplicate/missing/unknown fields, nonintegers, invalid encoding, unsupported format/minWriter, mismatched target, wrong key, bytes/size/hash mismatch. Only accepted arch x64/arm64 = installed CPU, version exactly three nonnegative canonical SemVer integers optionally -beta.N; channel must agree with suffix; stable allows stable only, beta allows newer stable or beta per appUpdater.ts:378–380. Strict numerical SemVer ordering (stable greater than beta of same core), never equality/downgrade incl channel switch. Fixed ceiling 2 GiB per AppImage; check space, enforce bytes limit while receiving. No install path/command/origin/key in manifest. Use production desktop public key embedded in bootstrap and installed verifier; test key is separate build-only trust domain. CI signs after final packaging, verifies metadata version/size/hash/arch against actual final bytes and validates positive and rejection vectors before publishing feed last. Unprivileged client uses version/sidecar to request; only writer enforces trust, never trusts request's claim of installed version.

44: Writer-authoritative committed state is the fixed regular **inode with two user xattrs on that same inode**: user.autobyteus.release = exact signed bytes, user.autobyteus.signature = raw signature. First provisioning verifies and writes file+xattrs, fsync then same-filesystem rename and parent fsync; require installed FS supports user xattrs/rename/fsync, check BEFORE publishing menu/profile. Incoming signed image staged privately under writer UID; verify, set attrs, read back, fsync before reporting receipt. Opaque stage ID bound to peer UID, current live digest, signed candidate and generation. At activate lock store, re-open live without following symlinks; verify its xattrs, use signed current record as sole version authority; compare expected digest, admissibility and channel again. After interruption or on new writer start, hash actual live bytes against signed metadata before trusting baseline. No second version file, unlink-first or symlink selector. rename incoming over live, fsync containing directory before ACK. Crash before rename leaves old image+old record; after rename one complete pair is visible; crash before fsync or lost ACK → status re-reads and verifies actual fixed inode, reports old/new identity; do not guess or report success prematurely. Incomplete/unverifiable committed pair → fail closed, explicit repair, not version zero. Pending files disposable on restart, conservative discard; never discard live. Write access only to service account; root code/keys/config outside writable store. Real filesystems must be tested, local inode feasibility probe is not power-loss validation.
45: Example: bootstrap installs signed 1.5.13; on beta channel 1.5.14-beta.1 accepted from that digest, then 1.5.14 stable from beta digest; stale stage referencing 1.5.13, same-version alternate bytes, beta in stable mode or unauthenticated 1.5.15 all refused. Queries return writer's current signed identity, not client running version. Add client stage/activate/discard/status and contract golden vectors; no app-data migration. FS xattrs not preserved by arbitrary cp; supported installer writes them itself, external copies never count as authoritative managed installs.
