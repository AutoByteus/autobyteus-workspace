## Evidence And ARCH-REV-001 Finding Resolution

The published AppImage on local Ubuntu 26.04 aborts on no-flag direct launch with exit 133 and a Chromium `FATAL:sandbox/linux/suid/client/setuid_sandbox_host.cc` message **before AutoByteus bootstrap**; correct `--no-sandbox` starts app/server. The FUSE mount is `nosuid`, helper mode 755, and kernel audit shows AppArmor namespace capability denial. `evidence/probe-classifier-current-host.txt` records `/usr/bin/unshare -Ur true` failing to write `uid_map` with EPERM on this host. This is one correlated restricted-host case, not proof that every failed or missing `unshare` means Chromium cannot sandbox. The embedded v1.4.78 desktop entry also unconditionally passes `--no-sandbox`, while `AppRun` forwards direct CLI arguments; builder 25.1.8 source explains the divergence.

- **F-001 / MP-001 (security decision):** The SR-004 design's generic negative/missing-probe → `--no-sandbox` branch is **removed**. SR-005 retains a positive `unshare` probe only as a fast path to normal sandboxed Electron `exec`. For any negative, absent, timed-out or ambiguous probe, the wrapper runs the **actual packaged Electron ELF without the flag** once. It streams stderr while retaining only a bounded exact-fatal marker, forwards signals and waits. Only an exit 133 within 30 seconds **and** the exact locally observed Chromium pre-start sandbox FATAL permits one automatic `--no-sandbox` retry. A sandbox-capable host with a spuriously failing/missing probe remains sandboxed, because its first real Electron process keeps running. An unrelated crash, late failure or unrecognized signature never triggers the downgrade. The design specifies bounded output matching, private cleanup, exact argv, exit/status forwarding and tests. This changes technical mechanism, not approved behavior. Positive probe remains an approximation, requiring actual packaged renderer-isolation validation.
- **F-002 (canonical coherence):** `investigation-notes.md` now maps SCN-001–004 exactly to approved requirements. Manual correct flag and the `--no-sandobx` typo are diagnostic probes without canonical scenario IDs. The notes contain a current supplement inventory with owner, purpose/scope, status and approval applicability; Round 1 review artifacts remain reviewer-owned and Blocked.

The underlying package mechanism otherwise remains: AppImage-specific `afterPack` hook transforms the unpacked ELF into a sibling real binary and common package launcher, a nonempty private desktop marker neutralizes builder's unconditional generated flag and is stripped by the launcher, Node mode bypasses GUI sandbox decision, and existing release/updater gates are extended. The narrow Mac hook extraction, startup diagnostic, no data migration and no host policy changes remain in the design.
