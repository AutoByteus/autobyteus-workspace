## User Explanation — “How Does It Work in the Future?” (2026-09-24)

This is an informational explanation of the already approved SR-005 design, not a requirements change, new solution revision, review request, or implementation handoff. A user launches the future AppImage normally, with no special flag. Its package launcher first checks whether user namespaces appear usable. A positive check launches Electron normally with Chromium sandboxing. If the check fails or is missing, the launcher still tries the actual Electron application **with** sandboxing; a working application remains sandboxed. Only if that attempt promptly aborts with the specific known Chromium sandbox startup fatal does the launcher retry once with `--no-sandbox` and log a warning. Unrelated startup errors do not disable the sandbox. The same decision applies to direct and desktop-integrated launch; explicit caller flags and Node-mode/server invocation are preserved. No host AppArmor/sysctl setting is changed. The fallback trades Chromium process isolation for startup only on the affected launch.
