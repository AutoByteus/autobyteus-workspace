## SR-011 approved correction — configured-price SDK estimate

**Approval and decision history, 2026-09-23:** The user first considered retaining the SDK's estimate after learning that `costUSD` is not a subscription charge, then explicitly chose the pre-existing Autobyteus pricing approach: “if earlier we already calculated by ourselves, we already have the algorithm ... from the origin personal branch, then let's just calculate by ourselves since it's still just estimation. ... not change that.” When the Solution Designer identified the cache-write 5m/1h ambiguity, the user directed: “Please update the design ... since it's only estimation ... pick one reasonable ... for the cache stuff.” This delegates a reasonable approximation choice. The chosen policy is exact selected-model reconciliation of the SDK's available main-loop duration split first, then a visibly approximate configured 1-hour write rate when that split is unavailable/unreconciled. The latter is a rate assumption, **not** a claim that the SDK used 1-hour cache in every turn.

The user clarified that Autobyteus historically maps model identity to its **own configured price** and calculates the Token Meter's API-equivalent estimate. They questioned showing the Claude Agent SDK's `costUSD` because they use a fixed subscription and that number is not an actual incremental charge. This is an intended-behavior change to SR-009's SDK cost source, not proof that the subscription is free of limits/overages. See I-37/I-38. The selected-model-only token policy, SDK identity matching, old records, direct Messages price row and no-Haiku display remain unchanged.

**Desired behavior:** For a selected SDK Opus run, use the SDK's selected-model token counts/deltas but price them with the configured `claude-opus-5-5` schedule in Autobyteus, using the selected entry's SDK-provided `canonicalModel` as **price identity only after** a unique selected alias→SDK raw-entry match. This yields a labeled **configured API-equivalent estimate, not subscription spend**. Do **not** use SDK `costUSD` as the displayed price or as an inferred cache-write rate; do not price Haiku or use a raw `[1m]` alias/static duplicate row. If canonical price identity or a required rate is unavailable, show missing/partial, never zero or an invented price.

**Cache-write decision:** The configured Opus row has different 5-minute and 1-hour cache-write prices ($5/$8 per MTok), while the SDK's per-model row reports only aggregate cache-creation tokens. A new real Opus-selected probe (I-41) found `usage.cache_creation` 5m=0/1h=7140 and selected Opus aggregate=7140, with all other top-level token counts matching the selected per-model counts. Thus exact reconciliation can use the SDK-reported split in that turn. Because top-level `usage` covers only the main loop and per-model `modelUsage` also covers other query-pipeline calls, a mismatched turn must **not** transfer top-level 5m/1h quantities to the selected model. For positive selected cache writes without a fully reconciled split, use the configured **1-hour** write rate as a visibly marked approximation: it matched the observed Opus probe and is the higher of the two configured rates, so it avoids a silent 5-minute undercount in that observed shape. It may overestimate a mixed/5-minute turn. Missing 1h rate remains partial, not zero. Zero writes need no assumption.

Further live create→resume and tool-bearing return-shape probes (I-42/I-43) support this strict reconciliation path in those observed turns; they do not change the approved fallback or establish universal equality. Streamed assistant-frame usage can be non-final and is not an alternative accounting source. I-44 records a tool-probe permission-guard limitation without changing the numeric result observations.

AC-011–013 above are the authoritative current criteria. The rate snapshot is chosen at observation time; selected token deltas are priced from trusted dimensions, with an explicit approximation marker if the 1h fallback is used. The Token Meter labels the result `Configured API-equivalent estimate — not a subscription charge`. Tests must show SDK `costUSD` can differ without altering this estimate and historical snapshots are not repriced.

**Approval status:** **Approved SR-011** by the two quoted user instructions; the Solution Designer's delegated cache approximation is justified by I-41 and bounded by the visibility/partial guards above. SR-012 is the revised monetary design and requires independent review before implementation proceeds. Selected-model-only behavior under SR-009 remains approved.
