## Environments and method

- **Build/fixture:** Ubuntu 26.04 x64, Node 22.23.2, pinned Go 1.27.4. Independently verified the IR-001 signed x64 .3 image (SHA-256 `086af959f4f4305c45a77655bd9e2b0a88a04d9816c7dd734929b4a5977a237a`). It was **these exact bytes** that the existing .2 writer activated and the prior download redirected to. For initial enrollments only, used full AppImages repacked with the respective released-source/current native tools, compile-time `desktop_test` loopback transport and build-only key; preserved actual Electron application, server, artwork and normal system authorization. Original released .2 download was retained untouched for the later redirect. No production private key, public release, enrollment bypass or runtime trust override. Public feed transport is not a test target.
- **Realistic system:** newly provisioned KVM guest from checksum-verified Ubuntu 24.04.5 x64 image, GNOME Shell 46 / Ubuntu Dock 90ubuntu3 enabled, real GDM seat and Wayland compositor with XWayland. AppArmor and Ubuntu user-namespace restriction enabled. Guest-local synthetic 1000 admin login with preexisting favorite and distinct 1001 admin login with default favorites and no prior install. Ordinary GNOME Terminal, zenity, graphical polkit, systemd writer, guest applications menu/search and rendered Electron. Loopback access only for new outbound app-user connections. No host profile, display session, desktop settings or installation mounted in the guest.
- **Measurement:** native Shell observer read `Shell.WindowTracker.get_window_app(window).get_id()`, actual Mutter client type, app system and favorites. Captured the **guest display** separately. The JSON + PNG pairs have the same basename. For two windows, used Nodes → add a synthetic loopback entry → Open node; the second node need not offer a live service to create a real node-bound BrowserWindow. Guest QA selected X11 via `--ozone-platform=x11`; independently observed X11 from Mutter on the Wayland compositor. Default launches used no backend flag. No forced cache refresh, Shell restart or product delay to repair the presentation. A session change was used solely to enter the separate virgin login.
- **Repository evidence reused:** IMP-02 both typechecks and 33 Electron tests; IMP-05 complete clean frozen-install build from matching production source, signed bytes and embedded artwork. QA-only fixture module is outside the app/build. These are not credited as live window proof. Non-Ubuntu platforms, standalone Xorg, other Dock versions/themes and public CI release are **not tested**; X11 coverage here is XWayland, as allowed.
