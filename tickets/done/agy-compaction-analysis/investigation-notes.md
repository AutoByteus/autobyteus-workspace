## Manual compaction command — experiments
- A10 (stream-json, like AutoByteus): after "Reply with exactly: OK ONE", the user message `/compact` was sent as `{"event":"user",...}`. AGY streamed user_input, then agent_response "Conversation history compacted. How can I help you next?" in ~1.8 s. Cumulative input tokens kept growing (11,868 → 23,806 → 35,827). The transcript shows `<USER_REQUEST>/compact</USER_REQUEST>` followed by a model reply, with no CHECKPOINT. **The model faked the compaction**; nothing was compacted (probes/agy-stream-manual-compact-raw.jsonl).
- A11 (one-shot print mode): `agy -p "/compact" --conversation <id> --output-format stream-json` gives the same fake reply, plus a routine system_message ("server restart" notice on resume). No CHECKPOINT.
- A12: `agy -p "/help"` lists the commands print mode answers: /agents, /changelog, /config, /credits, /effort, /help, /hooks, /model, /permissions, /skills, /usage. No compact. Despite the changelog's "explicit refusal for interactive-only slash commands", `/compact` is not refused; it falls through to the model.
- A13 (interactive TUI via tmux, same conversation): typing `/compact` shows "No matches" in the command picker. The full list of 45 interactive commands (probes/agy-tui-slash-commands.txt) has no compaction command; `/context` only visualizes usage (window 1.0M tokens for gemini-3.8-flash-low). The binary contains the description "Compact the conversation now (summarize history to free up the context window)." and internal identifiers (manualCompactionRequested, ParseCompactRequest, IsCompactUserInput, nothingToCompact, compactionfailed), but 1.2.16 exposes no command for it (hidden or unreleased). A bare Python pty attempt failed because the TUI waits for terminal capability replies; tmux worked.
- A14 (other control surfaces): compaction_threshold and the `on_compaction` lifecycle hook exist only in the internal `antigravity.localharness` config proto, not in the agent Markdown frontmatter or the CLI hooks. CLI `hooks.json` events (per the changelog and the exa.hooks_pb proto) are PreToolUse/PostToolUse, PreInvocation/PostInvocation, Stop and SessionStart; there is no compaction hook. No CLI flag or setting for the compaction threshold was found.
- Conclusion: AGY 1.2.16 offers no supported way for AutoByteus to trigger compaction. `/compact` sent as a message is answered falsely by the model, which matters for users today.

## Automatic compaction — experiment
- A15 (probes/agy-stream-auto-compaction-raw.jsonl; stream-json; 6 data dumps of ~90K tokens each, then a short message): turns 1–4 had cumulative input of 91,676 / 173,183 / 256,778 / 338,362. On turn 5, after `user_input` (step 8), AGY emitted **`{"event":"step_update","step_update":{"conversation_id":"06e020e6-…","step_index":9,"state":"DONE","step_type":"checkpoint","duration_seconds":7.719925}}`**, then the agent_response, inside the same turn. There was exactly one checkpoint update, with no ACTIVE/started state and no summary text or token figures in the stream. Later turns used small inputs (turn 7 added ~2.4K input tokens), consistent with compacted context. The transcript has a matching `CHECKPOINT` at step 9 with a 12.7K-character "# Resuming from a compaction" summary (transcript_full).
- A16: the compaction trigger occurred well below the 1.0M window (~340K accumulated, similar to community reports of 140–260K per segment and the 237K real case); it is not tunable through the CLI (A14).
- Not observed: a compaction failure or interrupt during compaction (no way to trigger it on demand). `compactionfailed` exists internally; its stream representation is unknown (possibly a checkpoint step with state ERROR, or nothing).

## Feasibility read (evidence only; no design selected)
- Detection: feasible from the existing stream. `step_update` with `step_type:"checkpoint"` and `state:"DONE"` marks a completed compaction, at a stable `step_index` inside the active turn. AutoByteus currently drops it (A03).
- Identity: conversation_id + step_index is stable across restarts (persisted step index), suitable as a boundary key.
- Lifecycle: only completion is signalled, with duration. A started phase cannot be shown live; failure signalling is unknown.
- Metadata: duration from the stream; summary and token figures are available only from AGY's transcript files (A06) or derived from cumulative result usage.
- Manual trigger: not available in AGY 1.2.16 (A10–A14). Live E2E for this would need large-context auto compaction (~4 large turns; seconds per turn on flash-low).
- Risk: older AGY versions emit non-compaction "CHECKPOINT 0" steps early (A08); without a version gate these could be misread as compactions if the old stream also labels them `checkpoint`.

## Repeat experiment — reproducibility (2026-10-04)
- U02 (User): asks for certainty that feasibility rests on real experiments.
- A17 (probes/agy-stream-auto-compaction-twice-raw.jsonl; same stream-json launch; 10 dumps of ~90K tokens each, then a short message; conversation 5bd8c148-aa5c-4f18-a0e8-1c2f52782771): two automatic compactions in one conversation, each streamed exactly once as `step_update {step_type:"checkpoint", state:"DONE"}`: step_index 9 (turn 5, duration 7.29 s, after ~338K cumulative input) and step_index 18 (turn 9, duration 6.73 s). The transcript has CHECKPOINT steps at exactly 9 and 18 ("# Resuming from a compaction"), and no others. Same pattern as A15 (step 9 on turn 5), so the signal is reproducible and repeats per compaction with distinct step indices.
- Feasibility conclusion: detecting AGY automatic compaction from the stream and rotating raw traces per compaction is technically possible. Not possible in AGY 1.2.16: manual triggering (A10–A14) and a live "started" phase.
