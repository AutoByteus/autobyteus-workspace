## Every agent has semantic memory, and you can browse it

- **Semantic memory is on for every agent.** The "Semantic memory" switch is gone from the agent form, the agent page and personal settings. Every agent, in every runtime and every kind of run (standalone, delegated, team member, organization member, application-owned and internal agents), gets its own folder of reusable knowledge and is told where it is. The agent page now shows the folder's path for every agent. Folders that already exist are not touched, and a leftover "semantic memory" setting in an agent's file or in your personal settings is simply ignored (it disappears the next time that file is saved).
- **A global memory shared by every agent.** The node has one extra folder, `semantic-global`, for facts that are true for everyone: what the product is, the words it uses, your standing rules. Every agent is told about it right after its own semantic memory, and every agent may read and write it. The app only creates the folder when it is missing; everything in it is written by agents.
- **A new Memory page, organized by owner.** Browse now opens on tabs **Global · Agents · Agent Teams · Agent Orgs**, each with cards. An agent's page has **Episodic memory** (all of its runs, from every place it works, with a filter) and **Semantic memory** (its folder). A team's or organization's page lists its members, each opening that member's own page, and its runs. An agent shared by several teams has one memory and opens the same page from everywhere. Internal agents stay hidden until "Show internal agents" is on.
- **Read-only folder view.** The Semantic memory tab and the Global tab show the folder like the Skills page shows a skill: a file tree with search on the left, files opening in preview tabs on the right. Nothing in it can be edited, renamed, deleted or dragged from the app, and the node refuses such changes. Symbolic links are listed but never followed. Opening the view never creates a folder, and an empty or missing folder says so. For a memory source synced from another node, the page says semantic memory is not part of synced memory.
- **Long agent names no longer stop a run.** An agent whose ID is too long for a folder name (the agents bundled in applications have such IDs) used to be unable to create its memory folders and could fail to start. Its folders now get a shortened name, the same one for its semantic memory and its episodic catalog, and the Memory page finds them. If a memory folder can never be created (for example, no permission), the run still starts, without that memory, and the server log names the agent and the reason.
- Every agent's instructions now carry two short sections (about 130 words together): its own semantic memory and the global one. An agent on the AutoByteus runtime whose definition lists no file tool can see the folder's path but cannot use it until a file tool is added to its definition.

## What you need to do

- **Update the desktop app and every node you connect to together** (the desktop app, Docker nodes, paired nodes). The data behind the agent pages and the Memory page changed shape, so an older app with a newer node, or the reverse, can fail to load those pages.
- Nothing to do for your agents' memory folders: every agent keeps its folder name. Only an ID over 255 bytes once encoded, which could never have had a folder, gets a shortened name.
