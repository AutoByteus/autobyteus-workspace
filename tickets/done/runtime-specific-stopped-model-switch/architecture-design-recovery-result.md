## Corrected SR-009 Design
One ClaudeModelCatalog/backend normalization owner still turns a raw SDK snapshot into offered models plus an exact-ID resolver. ModelCatalogService exposes both semantics: offered-only `listLlmModels`/provider snapshots for **new choices**, and a named exact-current descriptor entrypoint for persisted/effective values. Stopped RunModelSelectionService keeps SR-007's coherent self-contained run-option descriptors and fresh Save split (changed target must be offered; unchanged exact current must still be SDK-reported/schema-valid).

For Agent/Team definition/new-run/mobile and Application Launch Setup Web forms, a separate batched read-only GraphQL descriptor query supplies the backend's exact current model metadata/schema for server-origin saved/seeded/inherited IDs. The picker shows this as current value, not a clickable new `default` row; offered options remain normalized. Selecting a listed sibling explicitly changes the ID; opening or leaving the form alone does not. The shared select no longer alias-matches `default` to `opus`; a current display override keeps the saved ID truthful. If raw SDK no longer reports the exact ID, show it as unavailable rather than guessing a mapping.

ApplicationLaunchHostCapabilityValidator resolves its effective saved leaf through ModelCatalogService's exact-current descriptor (including provider metadata needed for credential readiness), not offered-only `listLlmModels`. Existing runtime and credential checks remain. Design spines DS-07/08, backend/GraphQL/Web file map, clean-cut alias-removal sequence, tests and example are now explicit in the revised design. Persisted Agent/Team/Org records and definitions remain **Directly Usable — No Migration**.
