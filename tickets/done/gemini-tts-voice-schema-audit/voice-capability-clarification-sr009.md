# Solution Clarification — Verified Additional Google Voices Without Product Discovery (`SR-009`)

## Direct Correction To User
The user's interpretation is right: Google documents additional voices beyond Autobyteus's current 30. “Do not present the 30 as Google's complete catalog” meant only **do not label a fixed subset as exhaustive**. It did **not** mean we should refuse additional voices. A user-facing dynamic `voices.list` browsing feature is optional; accepting and exposing additional **real, tested** voice IDs for `generate_speech` is a separate improvement. The user's clarified rule is to include new speech capabilities only after they work in a suitable route-specific test.

## What The Experiments Actually Prove
- One exact `gemini-3.8-flash-tts` single-speaker speech request with the current Vertex Express key and existing default `Kore` voice succeeded and produced a validated 322,538-byte WAV on 2026-10-02.
- One distinct Vertex Express `voices.list` request failed HTTP 404. It did not test speech with any Extended Voice Library ID, nor did it call `voices.create` to design a voice. We **cannot** say creative voice design was tested and failed. Google's [Developer TTS guide](https://ai.google.dev/gemini-api/docs/speech-generation) and [Cloud TTS overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/text-to-speech/overview) describe larger libraries, but their catalog sizes and access surfaces differ; neither proves all IDs work on this Express key.
- The current adapter's hardcoded 30-value schema and runtime validation block additional IDs before Google can even evaluate them. A future safe change can remove that app-level block **only after** a real ID from a legitimate catalog source and the selected provider route have passed synthesis validation. A complete static catalog cannot truthfully be claimed from one sample. Google's [Voices API](https://ai.google.dev/api/voices) is the documented source of actual prebuilt IDs; the user has not requested a product-facing live discovery UI.
- Google's [Voice design](https://ai.google.dev/gemini-api/docs/voice-design) creates a persistent `voice_...` resource through the Voices `create` endpoint. It has not been tried. Because it is a provider mutation, a bounded create/audition/synthesize/delete experiment and suitable route/key must be explicitly agreed. Replication separately requires adult speaker reference and consent recordings and is not covered by a synthetic test.
