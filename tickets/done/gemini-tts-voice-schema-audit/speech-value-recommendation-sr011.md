## Recommendation and evidence versus judgment
1. **Highest-value first: single-speaker Extended voice ID support.** Keep the featured 30/default, but stop rejecting a legitimate prebuilt/Extended ID solely because it is absent from the 30-name enum. Advertise individually verified additions; accept caller-supplied IDs with honest provider errors, not an all-voices guarantee. One genuine extra `ar-001-advisor-1` generated 370,538-byte RIFF/WAVE on selected Vertex Express. This establishes feasibility, not every library voice or Arabic quality. Value judgment: removes an artificial capability ceiling and reduces pressure to maintain a giant static enum, without needing a voice creation/storage/credential lifecycle. That is a qualitative scope judgment, not a measured effort/cost claim or completed design classification.
2. **Next: distinct per-turn style for existing dialogue.** Preserve existing global style as fallback; allow narrator/guest turns to request different delivery. The two-speaker Kore/Puck probe generated 529,898-byte WAV. Value judgment: makes dialogue more useful/controllable without changing existing speaker count or creating identities. Limit: no audition/transcription; audible style compliance/order/directions-not-spoken remain AC-003 acceptance gates, not passed quality results.
3. **Do not integrate a new voice platform now.** Vertex Express synthetic create failed404 with no resource; global/full-Vertex/AI Studio design availability not determined. Replication untested, needs real adult reference/consent evidence. Dynamic discovery UI, streaming and format controls are outside approved/tested scope. Potential future value is not present route evidence. No repeated calls or silent mode switch to make these appear successful.

Recommended first integration is therefore **additional-ID selection plus per-turn delivery**, retaining 30 choices, Kore / 3.8 Flash defaults, separate Flash-Lite option, existing WAV/global-style behavior and clear errors. This matches existing SR-010 intended behavior; approval still required. The string-capable schema is not a promise that each supplied ID is usable, and verified choices must not imply the full catalog.
