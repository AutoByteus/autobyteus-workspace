## Findings From Code / Docs / Data / Logs

1. Mermaid's built-in fallback has the exact screenshot wording and icon shape.
2. Mermaid 11.12.3 default config contains suppressErrorRendering: false.
3. Mermaid's render implementation starts with root = select('body') when no container is supplied. On parse failure it creates the error diagram, stores the parse exception, and eventually throws; the temporary body subtree is removed only on successful completion or when suppression is enabled.
4. mermaidService.render calls mermaid.render without a caller-owned container and without suppression.
5. MermaidDiagram catches the error and displays a local card, but cannot undo the vendor's already-appended body subtree.
6. The outer shell has intentional overflow containment, so the body-level fallback bypasses the intended scroll owner and explains why the user can scroll below the application.
7. There is no evidence of URL/router mutation, native filesystem access, backend request, or persisted-data write in this path.
