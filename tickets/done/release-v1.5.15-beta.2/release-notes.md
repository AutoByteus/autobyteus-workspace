## What you need to do

- **From v1.5.15-beta.1: a normal update.** Nothing else to do. This beta adds no data conversion and no Docker system change (the server image is still system level 2, as in v1.5.14).
- **iPhone and iPad: update AutoByteus from TestFlight to the new build, version 1.5.15 (build @@IOS_BUILD@@).** The iPhone's video and audio player now uses iOS's own screen, and that change is in the app, so it needs the new build; an older build keeps the player of beta.1 with the app's Back bar over its buttons. It is a TestFlight beta only, and nothing is sent for App Store review. Every other change below reaches the phone with your node and the desktop app.
- **Android:** the app itself has no change since beta.1; the file viewer changes arrive with your node. Install the APK of this release if you want the matching version number.
- **Docker nodes:** a node already on v1.5.14 or on beta.1 updates in place. A node that is still on an older image (v1.5.13 or older) must be recreated once before it takes this beta: run `autobyteus-docker upgrade --all --tag beta`. The stable `:latest` image stays on v1.5.14.
- **Desktop:** with **Settings > Updates > Receive beta updates** on, the app updates itself to this beta.
- **Coming from v1.5.14 or older:** read the [beta.1 release notes](https://github.com/AutoByteus/autobyteus-workspace/releases/tag/v1.5.15-beta.1) first (running agents that survive a restart, the phone apps' video and audio player, word wrap and more highlighted file types). For v1.5.13 or older, also read the [v1.5.14 release notes](https://github.com/AutoByteus/autobyteus-workspace/releases/tag/v1.5.14): they have the steps that come with that release, among them the one-way conversion of saved organization runs on the first start, which cannot be undone, so do not install an older version afterwards.

## What's new since v1.5.15-beta.1

- **The file viewer shows no line numbers.** Text, code, JSON and Markdown source open with only a small margin before the first character, so the text uses the whole width, on the phone and on the desktop. Editing and saving on the desktop work as before.
- **An attachment with no content says so.** A video or audio attachment of zero bytes in a Team or Organization message no longer shows "Failed to fetch reference content (416)", as it did in beta.1. The viewer opens and says "This video could not be played." with **Retry** (in the phone apps, the player's "could not be played" screen). An attachment that was deleted still says it is unavailable.
- **The iPhone's video and audio player is iOS's own screen.** It has iOS's close button and the file's name on top, with nothing of the app over its controls: the app's **Back** bar that sat over the player's top buttons in beta.1 is gone. Close it with that button or by swiping down: the playback and its sound stop. A wide video still turns the phone to landscape. This needs the new TestFlight build (above).
- **Opening many PDFs no longer grows the app's memory.** Every PDF is drawn by one shared worker instead of a new one for each document, in the desktop app and on the phone.
- **A file message about one run no longer follows you to another.** The line under a conversation that says a file could not be opened (for example, a file on another node) clears when you switch runs.
- **Agents' system prompt is shorter: the long-running-commands section is gone.** Since v1.5.13, Claude, Codex, Grok, Antigravity, DeepSeek and native AutoByteus agents were told, at the end of their system prompt, how to start a long build or test suite once in the background, act on its completion notice and not wait with sleep loops. That text is removed from all of them, and nothing else in the prompt changes. New runs and restored runs get the shorter prompt; a saved run keeps the prompt it started with until it is restored. The habit is kept as a best-practice note in the node's global memory ("Best practice: long-running commands"), where any agent can read it, and each runtime's own shell tool still describes its background runs. Claude's 2-hour shell limit and the background-task display do not change.

## Good to know

- How well agents wait for a long job without the removed section was never measured, before or after. If an agent starts a job twice or waits with sleep loops, tell it to read the global-memory note, or put the habit in that agent's own instructions.
- On iPhone, the sound with the Ring/Silent switch on silent and a screen lock have been checked on a simulator, not on a physical iPhone.
- The known issues of beta.1 about the iPhone's Back bar over the player's buttons and the "416" message for an empty attachment are fixed in this beta. A swipe down now closes the iPhone's player.
- The rest of the beta.1 list still holds: the new player needs the new app and a node on this beta (an older app, the node's web page in a phone browser and the desktop app play videos and audio in the page); on Android, if the system switches dark mode while a video plays, the player shows "This video could not be played." (press **Back**, then **Play**); on a connection slower than the video itself, the iPhone plays at the speed of the connection.
