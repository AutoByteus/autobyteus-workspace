## Delivery Summary

- Delivered scope:
  - Each agent definition that has runs on this node gets an **episodic catalog**: `<memory>/episodic/<encoded definition id>/catalog.md`, named like its semantic memory folder, listing every run of that agent oldest first: start and last activity (UTC), run ID, the title of the Project Task the run worked on (when it has one), the workspace, and the run's Work Journal folder with each file's name, time range and size, or "no journal yet". `<memory>/episodic/index.md` lists every catalogued agent. Runs of every kind land in the one catalog of their agent: standalone, delegated copy, task agent, team member (also a team-local agent), org member.
  - Privacy: no text from a message, tool call, tool result, journal line or Task description, and never the run-history summary (the user's first message); the entry holds no team or org context, delegation, node, runtime, run state, Task key or file state.
  - Upkeep: a journal change queues the run's root; a pass starts 5 s after the latest request and at most 30 s after the oldest (a burst of four turns gave one rewrite). A committed delete of an agent, team or org run removes its entries; archive changes nothing; a refused delete changes nothing. Every start rebuilds the catalogs in the background from the run records and the journal files' headers, writes only catalogs whose content differs (a restart with no change writes nothing) and heals a hand-edited file. The feature writes only under `<memory>/episodic/`.
  - Containment: a catalog failure is logged and never reaches a run, a journal update or a delete. A team or org tree, an agent run's `run_metadata.json` or a journal manifest that cannot be read leaves that run out with one warning naming the root or run, the record and the reason (`RUN_FOLDER_DISCOVERY_RECORD_UNREADABLE`, `EPISODIC_CATALOG_RUN_LEFT_OUT`); every other run is catalogued.
  - Structure: `src/agent-episodic-catalog/` (owner `EpisodicCatalog`, entry builder, renderer, store) follows the Work Journal module's shape. The shared "which run folders exist and whose are they" moved from memory search to `agent-memory/services/run-folder-discovery.ts` (`RunFolderDiscovery`, `DiscoveredRun`), with three explicit attributions (`attributed`, `unattributed`, `unreadable`); memory search keeps only its mapping to `MemoryRun`. `WorkJournalService.readJournalSpans` reads the journal files' header spans. Both composition roots that run agents (`buildStudioServer`, `startStandaloneApplicationHost`) keep the catalogs; the three run-delete owners tell the catalog after a committed delete.
- Docs synced (`docs-sync-report.md`): `agent_episodic_catalog.md` (contract link by archived path, formatting rules, the record label of a package-level diagnostic) and `run_history.md` (the delete hook). Already written by the implementation and checked against the final state: `GLOSSARY.md`, `agent_memory.md`, `agent_work_journal.md`, `memory_search.md`, the modules README. `DESIGN.md`, `TESTING.md` and `RELEASE.md` need no change.
- Durable coverage: the gated server E2E `tests/e2e/memory/episodic-catalog.e2e.test.ts` (7 cases, about 5 minutes: real runs of every kind, GraphQL archive and delete, an unwritable folder, built-server stop and start on the same data; only the AGY CLI is scripted) and unit tests for the discovery, the catalog, its store, renderer and entry builder, the journal spans and the delete hooks.
