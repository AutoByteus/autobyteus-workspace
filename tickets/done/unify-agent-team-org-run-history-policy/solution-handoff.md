## Confirmed problem, user path and SR-005 correction

The original ticket is true: Team and Org catalogs had different authority/init/write/cache behavior. SR-004 designed a shared family-keyed index-only catalog core with specialized lifecycle adapters, Team manager-gated archive/unarchive compensation, no Org pre-create history initialization, read-only owner queries, and offline/local repair. Existing valid eight-field Team/Org index arrays remain **Directly Usable — No Migration**; no tree/index schema or path change. IR-001 implemented that reviewed basis and focused checks passed, but the latest API/E2E round uncovered an approved AC-003 gap in the **existing Team Memory explorer**.

The supported scenario is a user selecting an imported source in Memory and opening **Agent Teams** or a Team's run list. Web Memory page/store → `listAgentTeamsWithMemory` or `listAgentTeamRunsWithMemory` GraphQL → source resolver → new `TeamMemoryExplorerService(importRoot)` → catalog owner + root tree/member memory summaries → visible cards. The explorer reads each admitted root tree once; then, for every root, its member-target builder calls `AgentMemoryLocationService.listTeamMemberLocations`, which calls **unscoped** `TeamRunExecutionTreeLocationService.listAgents()` and rereads all stored roots. Three admitted roots yielded **12 post-readiness tree reads**, versus AC-003 at most three. The source defect predates `b68847a8c` (that commit only renamed a manager stub there); it is not a shared-catalog regression. SR-004's conditional Memory branch route covered an absent Org adapter but inadequately deferred this present Team path.

SR-005 retains the approved bound and puts the Team correction in the current package. `TeamMemoryExplorerService.buildGroups()` passes the **same already-read validated tree** into `TeamMemoryMemberTargetBuilder`; `AgentMemoryLocationService` obtains locations from an explicit no-I/O tree-scoped method in `TeamRunExecutionTreeLocationService` that reuses `TeamExecutionIndex` and existing physical-path/configured-placement logic. No all-roots lookup occurs inside the per-root loop. Preserve nested member identity, paths, available-memory cards, filtering, grouping, sorting, unreadable-tree handling and admission; no frontend/public GraphQL contract or persisted-data change. The unmerged Org root-memory adapter remains conditional: after merge, switch its direct index-store read to `AgentOrgRunHistoryCatalogService.listCatalogRows()` without a second tree scan. Do not claim that absent adapter is presently implemented or validated.

The L-03 probe correctly instruments `TeamRunExecutionTreeStore.read` **after** explicit readiness and fails its count assertion. Its `allFileBytesUnchanged` field is hard-coded `true`, despite collecting hashes; therefore the literal is **not** evidence of byte identity. Revalidation must genuinely compare before/after hashes of the imported copy, instrument both Team list endpoints independently, and verify member/card content. No product source or downstream-owned report was changed by this Solution Designer round.
