### SR-007 — Root-locked current-state message append

- Triggering role, report path, and round: `architecture_reviewer`; ARCH-REV-002 / Round 2 at `design-review-report.md` and `architecture-review-revision-record.md`.

- Current authoritative result: SR-007 resolves DR-004 and passes refreshed solution self-validation; implementation remains blocked pending complete architecture re-review.
- Why this revision is recorded: two independently supported same-root `send_message_to` calls can overlap. Physical write serialization is insufficient when each caller has already derived `M0+A` or `M0+B` outside the lock.
- Resolution: replace the full-snapshot interface with one `PreparedTeamMessageAppend` submitted immediately after synchronous AgentRun reservation. `TeamRunPersistenceCoordinator.commitReservedMessageAppend(plan)` acquires the existing root lock before the plan reads the service-owned current state, validates root/endpoints/reservation/message-ID absence, derives/validates current-plus-message, writes the file, swaps immutable memory, commits the preallocated event slot/reservation, and releases the FIFO entry. Conflict/write failure cancels before release. Same-receiver order follows reservation/plan submission; different receivers retain every row in root commit order. Root close rejects new plans, drains prior plans, then quiesces AgentRuns, preventing lock/reservation deadlock. No persisted revision, retry, replay, outbox, second input queue, or fourth file is introduced.
