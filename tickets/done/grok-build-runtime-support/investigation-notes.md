## Requirement Implications

- Grok Build fits the **same product contract as Codex/Claude/AGY**; it is closest to AGY in process shape (per-run child over stdio) and to Claude in capability (interactive approvals, HTTP MCP, skill symlinks, `sessionId` resume). No evidence requires a different product model.
- Because Grok supports interactive approvals, the AGY-specific "default auto-execute on" launch policy must **not** be extended to Grok; Grok keeps the standard default.
- Grok-specific facts shaping requirements: MCP discovery/indirection (canonicalization + prompt hint + readiness gate); no image prompt blocks; catalog depends on auth/plan and must come from the connected agent.
- `autobyteus-ts` change is content-only: `grok-4.7` replaces `grok-4.6` without alias; a stale integration test still expects `grok-4.5` and must be corrected.

## Notes For Architecture Design

- Scenario IDs to map after approval: SCN-001..SCN-010 / BEH-001..BEH-012.
- Verified constraints: one `grok agent stdio` process speaks JSON-RPC on stdin/stdout; `--model`/`--reasoning-effort` are process flags and session `configOptions`; `session/new` needs `cwd` + `mcpServers`; `_meta.rules` appends to the system prompt; `_meta.yoloMode` per session; `session/request_permission` is a blocking JSON-RPC request; `session/cancel` is a notification; `session/load` needs `sessionId` + `cwd` and replays history before returning.
- Technical questions for design: process-per-run (AGY/Claude-like) vs shared process; JSON-RPC client structure and request/notification routing; suppressing `session/load` replay from the live stream; usage mapping (`turn_completed` per turn, `response_completed` per call) without double counting; canonicalization of `use_tool`/`search_tool`; representation of Grok built-ins (`list_dir`, `run_terminal_command`, `read_file`, `search_replace`, `grep`, `web_search`, `todo_write`); `FILE_CHANGE` derivation for the Artifacts tab; termination (`session/close` vs SIGTERM); application credential authority case; safe diagnostic codes for availability/catalog failures (AGY pattern).
