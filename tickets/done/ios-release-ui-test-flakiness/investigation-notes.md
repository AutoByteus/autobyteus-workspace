- I04 (Run history, `gh run list --workflow release-ios.yml`): every run through v1.4.92-beta.5 (2026-10-01 09:56) passed on attempt 1; from v1.4.92-beta.6 (14:18), 6 of 16 needed attempt 2 (beta.6, beta.10, 1.4.93-beta.2, 1.4.94-beta.3, beta.4, beta.5).
- I05 (Runner image ruled out): every Build And Test job attempt from v1.4.92-beta.1 to v1.4.94-beta.5, pass or fail, ran on Image macos-26-arm64 Version 20260828.587 with the same Xcode 26 (job log headers; /tmp/ios-probe/log-*.txt).
- I06 (Code change ruled out): `git diff --stat v1.4.92-beta.5 v1.4.92-beta.6 -- autobyteus-ios .github scripts` is empty.
- I07 (Failure mechanism, run 37257062119 attempt 1, artifact 11322863308): the simulator was extremely slow (app launch → idle 21 s vs ~3 s on a fast pass; each tap several seconds). After Connect, the app's status request to the fake node hit the app's 5 s URLSession timeout (AutoByteusMobileCore/ConnectionValidator.swift:67-74, timeoutSeconds 5, no retry; AppShellCoordinator.swift:10 uses the default). The failure screenshot (probes/beta5-attempt1-failure-screen.png) and the UI hierarchy show "AutoByteus node is unreachable — The request timed out before the desktop node responded." So the WebView is never opened, and both assertions fail. The fake server logged the request only at 03:02:37 (~48 s after the Connect tap), and its response failed with BrokenPipe because the app had already closed the connection (probes/beta5-attempt1-fake-mobile-server.log). Passing reruns: WebView ~2 s after Connect.
- Root cause (evidence-based): a fixed 5 s connection timeout in the app versus intermittently very slow GitHub-hosted simulator hosts. Why slowness increased from 2026-10-01 is not attributable to our code or the image; most likely host load/hardware in the hosted pool (not provable from our side).
- U01 (User, 2026-10-05): the iOS app is not in use; Apple requires a test environment for review that the user cannot provide yet.

The restored launch in testFakeNodeOpens… creates a new XCUIApplication without launch environment.
- I13 (Safe CI proof path): release-ios.yml manual dispatch sets publish_requested from publish_app_store_connect (default false); publish-secret-gate and upload-testflight run only when publish_requested == 'true'. Concurrency group ios-release-${release_tag || ref_name || run_id} with cancel-in-progress false: dispatches on the same branch without release_tag share one group, so at most one runs and one waits (extra pending runs are cancelled) → dispatch sequentially.
