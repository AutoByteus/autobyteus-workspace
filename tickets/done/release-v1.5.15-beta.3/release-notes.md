## What you need to do

- **From v1.5.15-beta.2: a normal update, with one exception: Voice Input has to be installed again.** The first time the new version starts, it removes the old built-in Voice Input install once, in the background (the old install is no longer used, and its files are deleted from your computer). Voice Input is now an extension. To dictate again, open **Settings → Extensions**, press **Install** on Voice Input (it downloads about 2 GB, once, and takes a few minutes), and choose your language and microphone again: your language and microphone choice from the old install are not carried over. Do this on the computer you dictate at: Voice Input belongs to that computer's own node. Until it is installed, the microphone buttons stay hidden.
- **Sandboxes need Docker.** Agents can now run an agent package in a disposable node in its own container. That works on a Mac with Docker Desktop running for now; other computers say so and create nothing. You do not need Docker for anything else in this beta.
- **Provider login through a relay is off, and not proven.** A node can now send its model calls through a paired node. Using a Claude `setup-token` login or a Grok sign-in for that (instead of an API key) is off by default, is new, and has not yet been tried against the providers with real logins. API keys are the tested way.
- **iPhone, iPad and Android:** the phone apps themselves have no change since beta.2. If you use TestFlight, the new build, version 1.5.15 (build @@IOS_BUILD@@), only matches this beta's version; it is a TestFlight beta only, and nothing is sent for App Store review. The phone apps show your node's pages, so what changes there comes with your node, not with the app.
- **Docker nodes:** a node already on v1.5.14 or a v1.5.15 beta updates in place. A node that is still on an older image (v1.5.13 or older) must be recreated once before it takes this beta: run `autobyteus-docker upgrade --all --tag beta`. The stable `:latest` image stays on v1.5.14.
- **Desktop:** with **Settings > Updates > Receive beta updates** on, the app updates itself to this beta.
- **Coming from v1.5.15-beta.1 or older:** read the [beta.2](https://github.com/AutoByteus/autobyteus-workspace/releases/tag/v1.5.15-beta.2) and [beta.1](https://github.com/AutoByteus/autobyteus-workspace/releases/tag/v1.5.15-beta.1) release notes first. For v1.5.13 or older, also read the [v1.5.14 release notes](https://github.com/AutoByteus/autobyteus-workspace/releases/tag/v1.5.14): they have the steps that come with that release, among them the one-way conversion of saved organization runs on the first start, which cannot be undone, so do not install an older version afterwards.

## What's new since v1.5.15-beta.2

- **Settings → Extensions: optional capabilities you install from Settings.** Every node now has a list of optional capabilities that AutoByteus offers. Each card says what the extension needs before you install it. You can install it, turn it on and off, update it and remove it. While it installs, the card shows what it is doing, and when something fails it shows the reason and lets you open the extension's log. When AutoByteus publishes a newer version of an extension, its card shows **Update**, with no new app version needed; your settings stay, and if an update fails the old version keeps working and the card says why. One broken extension never affects anything else.
- **Each node has its own extensions.** A Docker node or a Linux server lists and manages its own extensions in its own window, and only the node's owner can change them (a phone cannot). An extension that has no build for that node's computer says so on its card.
- **Voice Input is an extension.** It belongs to the computer you work at: you manage it in the window of this computer's own node, and every window can dictate with it, including windows of other nodes. Its card holds your language and, in the same place, a microphone choice and a **Test** button. While the speech model loads, Voice Input says "Getting ready" instead of looking idle, and the microphone appears when it can record.
- **Sandboxes: agents can run an agent package in a disposable node.** Three new agent tools, `create_sandbox`, `run_in_sandbox` and `destroy_sandbox`, let an agent run an agent package in a fresh AutoByteus node in its own container. The sandbox runs the same release as your node, is paired with your node as a peer, and holds **no API key and no login**: its model calls go through your node, which adds the credentials. Its workspace and run-memory folders are on your computer, so the agent reads what the package wrote and the transcripts directly. A sandbox is removed when the agent destroys it, when its lifetime ends (120 minutes by default, 480 at most), or when your node starts again. Your own agents, files and settings are never inside it. To use it: turn on Remote Collaboration in Settings, give an agent the three tools in its definition's tool list, and have Docker Desktop running on a Mac. At most four sandboxes run at once. An agent gives a sandbox its agent packages (copied in) and, optionally, folders it may read but not change; your home folder and folders that hold credentials are refused. The public skill `autobyteus-sandboxes` (in the AutoByteus skills package) tells an agent how to create a sandbox, delegate work to it, read the results safely and always destroy it.
- **A node can send its model calls through a paired node.** A node with a relay setting (the sandbox's, or one an owner sets on a node of their own) calls Claude, Codex, Grok, DeepSeek Harness and the AutoByteus native providers through the paired node, which attaches its own API key. The relayed node holds no provider key, and its Agent Runtimes page shows each runtime as signed in or out according to what the relay offers. The paired node accepts only nodes it is paired with and writes one line per relayed call to its activity log, with no key, token or request content in it. The Nodes page marks a paired node that your node created as a sandbox with a "sandbox" label.
- **The Memory page has a cleaner layout.** On an agent, team, org or run page, Back (showing where it goes), the name and the page's controls sit in one row, without the Browse, Search and Index tabs above it; the name stays visible at every window width. Browse, Search and Index remain on the Memory home pages. Cards no longer print the ID (hover over the name to see it). The semantic memory reader fills the window: its file list is 300 px wide with **Copy folder path** at its foot, the first document at the folder's root opens when you arrive, and the Work Journal fills the window too. A run with one journal file shows no file list and no picker; with two or more you get a list or a picker. Raw Traces has a single **Show** field that applies when you press Enter. A run's page is titled by its summary.
- **File lists show an icon for every kind of file.** In the Files panel, the Skills page and the Memory reader, JavaScript, TypeScript, Vue, HTML, CSS and JSON files, which showed blank or missing icons, now have their icons, and Markdown files have a document icon.

## Good to know

- **Extensions come only from AutoByteus's signed list.** A computer that cannot reach the list still shows the extensions it has installed, with a note that the list could not be reached.
- Going back to an older version of the app: the older app looks for its own Voice Input install, which this version removed, so you would install it there again.
- Voice Input on a Mac with Apple Silicon: its speech runtime needs `ffmpeg` (for example from Homebrew). If it cannot start, the card shows the reason ("Could not start: …").
- A sandbox has full network access, and your node treats it as any paired node: an agent in a sandbox can message the agents your node shares with its peers. Do not point an untrusted package at them. Antigravity agents cannot run in a sandbox or on a relayed node. Codex works through a relay with an API key only (Codex's ChatGPT sign-in cannot be relayed). Media generation tools and integrations such as GitHub are not available in a sandbox. Only the agent run that created a sandbox can use or remove it; anything it forgets is removed at its expiry or when your node starts. A development build has no published image to start a sandbox from and says so.
- A Grok login used through a relay is read as it is and never renewed, so an expired one asks you to sign in to Grok again.
