## Selected bounded design
1. Retain existing message_id/dedupe_key from original native input through MemoryManager/raw user record, normal memory reader/replay/conversation and frontend saved builder. Keep raw id/correlation/turn/sender meanings. Do not introduce identity allocation, sidecar, extra queue or new event.
2. Match inside exact recipient/node/sender scope using normalized primary messageId, otherwise tagged dedupeKey. Different IDs stay distinct even if body/time/secondary key match. Identified inputs never fall back to semantic matching; partial unknown identities are not guessed. Shared pure presentation helper, no registry.
3. One existing user-message projection owner handles pending overlay, preserving timestamp, identity, files/media/names and provenance. Handler keeps revision/block policy and delegates matching. Keep accepted-echo attachment policy separate to avoid regressions.
4. Explicit **stored-data affected additively; Directly Usable—No Migration**. Extend optional normal fields; old missing keys remain unknown/readable. No backfill/version/layout/startup-gate change or cold/restart queue promise. Fresh corrected writer history is the validation oracle; frozen old failing captures stay unchanged.
