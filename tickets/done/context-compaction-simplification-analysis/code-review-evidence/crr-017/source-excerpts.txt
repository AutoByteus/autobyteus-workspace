
### TESTING.md
14: | Layer | What it proves | Command |
15: | --- | --- | --- |
16: | Web unit and component tests | Nuxt renderer components, stores, utilities (colocated `__tests__`) | `pnpm -C autobyteus-web test:nuxt` |
17: | Electron main-process tests | Electron main, preload, launch profile, server manager, updater | `pnpm -C autobyteus-web test:electron` |
18: | All web tests | Both of the above | `pnpm -C autobyteus-web test` |
19: | Server tests | Backend unit, integration and E2E suites (Vitest) | `pnpm -C autobyteus-server-ts test` — one file: `pnpm -C autobyteus-server-ts exec vitest run <path> --no-watch` |
20: | Core library tests | `autobyteus-ts` agent runtime, tools, LLM layer | `pnpm -C autobyteus-ts test` |
21: | Other packages | SDKs, contracts, message gateway | `pnpm -C <package> test` (each package with a `test` script) |
22: | Server E2E (deterministic) | Server E2E suite with its own test-owned database and runtime | `pnpm test:e2e` |
23: | Real-provider E2E | Configured external providers, explicitly | `pnpm test:e2e:real:preflight`, then `pnpm test:e2e:real` |
24: | Codex runtime live E2E | Codex App Server transport | `RUN_CODEX_E2E=1 pnpm -C autobyteus-server-ts test -- --run` |
25: | Browser dev-path probes | Renderer journeys in headless Chrome | `pnpm -C autobyteus-web test:e2e:<name>` (scripts in `autobyteus-web/package.json`, sources in `autobyteus-web/tests/e2e/`) |
26: | Packaged Electron harness | Packaged app launch, isolation and cleanup | `pnpm -C autobyteus-web test:e2e:electron`, `test:e2e:electron:isolation`, `test:e2e:isolated-app` |
27: | Isolated desktop instances | The real desktop app, driven like a user | `pnpm --silent isolated-app start --build` (then drive with the browser-automation skill; `pnpm --silent isolated-app stop`) |
28: 
53: ## Choosing the path
54: 
55: Start with the smallest layer that directly proves the change, then add the
56: layer that closes the remaining confidence gap.
57: 
58: | The change affects… | Prove it with… |
59: | --- | --- |
60: | Backend logic, APIs, persistence, runtimes | Server tests (+ `pnpm test:e2e` for API journeys) |
61: | Core agent runtime or tools | `autobyteus-ts` tests (+ server tests for integration) |
62: | Renderer UI, stores, client–server behavior that also runs in a browser | Web unit tests + a browser dev-path probe |
63: | Desktop-shell behavior: Electron main process, preload/IPC, updater, windows, app lifecycle, embedded server startup, packaging | Electron main-process tests + an **isolated desktop instance** of a worktree build |
64: | A full real-product journey a user would perform | An **isolated desktop instance** of a worktree build |
65: | Behavior against real model or search providers | Real-provider E2E (preflight first), or an isolated instance with keys imported |
66: | Launch profile, isolation or packaged-launch mechanics | Packaged Electron harness |
67: 
68: Browser probes are fast and headless; use them for web-equivalent behavior.
69: An isolated desktop instance is slower (it needs an app build) but exercises the
70: real desktop app; use it whenever desktop-shell behavior or the full product
71: matters.
72: 
73: ## Rules
74: 
75: 1. **Test unreleased changes on a worktree build.** The installed app does not
76:    contain your change. Use `pnpm --silent isolated-app start --build` (or
77:    `--from-worktree` when that worktree's app is already built). Builds without
78:    isolated-launch support are refused with `APP_ISOLATION_UNSUPPORTED`.
79: 2. **Never test against the user's running AutoByteus** or its data
80:    (`~/.autobyteus`, the OS application-data folders). Only isolated instances,
81:    test-owned databases and the development stack are test targets.
