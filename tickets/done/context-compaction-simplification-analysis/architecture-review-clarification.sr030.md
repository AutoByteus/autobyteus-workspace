## Revised path and minimum ownership change

1. **Same memory gate, independent of turn lifetime.** One `{operationId,failureEpoch}` pending recovery identity, with position held_turn (unsent initial input) or next_turn (post-response consumed turn). Two existing executor callsites pass internal executionSite so failure records gate/position atomically before publishing. Strategy text interface untouched. No new queue, journal, outside-turn generation operation or tool safe point.
2. **Settle consumed A truthfully.** Post-response failure keeps the already-produced answer, emits separate compaction diagnostic/block, executes its normal final pipeline/hooks and completion once. A's command is completed/retired, not held. Worker remains alive and clears activeTurn; effective run status remains recoverable ERROR with pending gate even when currentTurn:NONE.
3. **Gate subsequent work at both owners.** AgentRun reconciles authoritative recovery snapshot before all claim/drain paths, including A completion. No next-turn grant means no drain despite no active turn. Core scheduler independently admits no turn_start while awaiting permission; lifecycle/stop lanes remain live. Remove queued USER-origin and different-turn ID as sufficient authorization everywhere.
4. **Fresh admission grants, FIFO determines next input.** Same supported user postUserMessage ingress/atomic admission claim; native control outside dispatch lock. A user after exhaustion but before A settlement grants only next-turn permission, never wakes/replays A. After real settlement + acknowledged grant, dispatch one oldest FIFO input. With prequeued B and fresh C, C authorizes but B then C remain ordered. No old/during-operation message generates a credit. Core binds the grant to that turn and consumes it at the existing pre-parent executor before its parent request.
5. **Retry failure changes position, not history.** If that new input cannot compact, it is still unsent: enter held_turn with a new epoch (DS009). Earlier consumed A remains completed. Another genuinely later user is required. A grant cannot be inherited by another input if its bound turn fails/cancels before the executor; revoke it. Known-undelivered server dispatch revokes only exact unused grant through narrow native control; uncertain delivery remains gated/reconciled rather than replayed.
6. **Status is a projection, not a fake active turn.** Core normal phase transitions and response hooks still execute once; recovery overrides effective public status rather than suppressing normal processing. Server/UI model error with active held turn OR completed/no active turn. Real A completion is accepted without clearing pending run failure; late block fact is not rejected just because its diagnostic failedTurnId retired. Validate run-instance/operation/epoch. Reconnect shows completed answer + error + queued inputs, not 'A never sent'. No backend reactivation just because ERROR/no active turn.
7. **Stop stays stop.** Revoke permission/fence inputs and interrupt real active work. No-active post-response state needs no synthetic waiter/turn. New state is in-memory only; no backend-restart outbox/persisted grant/migration.

These changes extend the already-planned coordinator permit, runtime control and server lifecycle/queue owners; they do not create a parallel retry service.
