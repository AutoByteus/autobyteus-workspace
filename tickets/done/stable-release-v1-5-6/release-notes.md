## Before You Update
- **Back up your data first. This update converts it, and you can't go back afterwards.** On the first start, AutoByteus converts your existing runs to a new storage format (details under Upgrade Notes). An older version can't read the converted data, so installing an older version after this update is not supported. To back up, quit AutoByteus and copy the `~/.autobyteus/server-data` folder (on a Docker node, the server's data volume). If you need to go back after updating, don't install an older version: open an issue at https://github.com/AutoByteus/autobyteus-workspace/issues and we will help.
- **Update the desktop app and every remote or Docker node it connects to together.** Different versions of the app and a node are not supported together. For example, an older desktop app connected to a node on this version shows no live text in Team, Org and delegated-agent chats, and no files for team, org or delegated members in Artifacts.

## What's New
- **Find Project Tasks by meaning.** Board search, on the Projects page and in the right panel, shows exact matches first, then Tasks that are about the same thing. A search that matches nothing says so. Agents can search the same way with the new `search_project_tasks` tool, for example to find an existing Task before creating a new one. Search runs on your machine: the first time you use it, AutoByteus downloads a small search model (IBM Granite Small English R2, about 55 MB) and checks it, and the board shows progress while it gets ready. Task text never leaves your machine. If meaning search is unavailable, the board says why, still shows exact matches and offers Retry.
- **Tasks can be part of a bigger Task.** Choose a parent in the new **Part of** field when you create or edit a Task, or use **New part** on the parent's Task page. There is one level: a part can't have parts of its own. A parent's card shows how many of its parts are done, and its Task page and the Projects tab list its parts with their status. Setting a parent to Done or Cancelled sets its open parts the same way and stops their task agents. Deleting a parent keeps its parts as separate Tasks. Agents can set, change and clear a Task's parent with the Project Task tools.
- **Work Journal.** Every agent run now keeps a Work Journal: a readable record of what the agent did, updated after each turn. Tool calls read the same on every runtime (Command, Write file, Edit file, Search web), and each entry links to its full record. Skill Improvement uses the Work Journal as its evidence.
- **Remote MCP servers that need sign-in now connect.** For remote (Streamable HTTP) MCP servers, the headers you configure, such as `Authorization: Basic …`, are sent on every request: connecting, previewing, listing tools and every tool call, on every agent runtime. The Token field is saved and sent as `Authorization: Bearer <token>`. Switching from the Form view to the JSON view shows the headers, and saving from the JSON view keeps them. Setting both a token and an `Authorization` header is rejected with a clear message instead of one silently replacing the other.
- **Each task agent keeps its own memory.** An agent or team that another agent delegates work to is now a run of its own, with its own conversation, files and message history. Long-running coordinators stay small, and the Memory page lists a task agent under its agent's name. Deleting a coordinating run from history removes only that run; its task agents are kept.

## Improvements
- **Runs with many delegated copies open quickly.** A run that delegated work to many agents or teams shows all of them right away, instead of after several seconds. A copy loads when you open it.
- **Artifacts open quickly for team, org and delegated members.** Opening a member's files no longer slows down as you collect saved runs. Files written by a team's or org's task agents now open like other members' files. While a team or org is still running, files that are still being written are listed, and opening one says it is not ready yet.
- **Smooth live text in every chat.** The **Live response streaming** setting now applies to Team, Org and delegated-agent chats as well as standalone Agent chats: text updates once per window (500 ms by default), and one update carries the text of every agent that is writing, in order. Standalone Agent chats again update at that window instead of many times a second.
- **Long runs stay fast.** Sending a message in a long-running agent, team or org run no longer slows down as the run's history grows.
- **Clearer "Skill updated" notices.** The notice names the skill that changed and lists exactly the files that changed, each marked changed, added or removed. When several skills change at once, each gets its own section, and a skill that was uninstalled says it is no longer available.
- **Workspaces that can't be opened are reported.** If a Claude or Codex run's workspace folder can't be opened, for example because it was moved or deleted, the run now stops with an error instead of quietly working in the temporary workspace. AutoByteus agents open their registered workspace instead of using the temporary workspace.
- **Quieter Codex server log.** When Codex finishes tool steps after a turn has ended, the server log records one line and a count per turn instead of one warning per event.

## Fixes
- **Claude agents: replies after background tasks no longer disappear.** When a Claude agent finished a background task and kept working on its own, its replies could be lost and the chat filled with "An Error Occurred" cards while the status showed Idle. The text now appears and is saved, and the status shows Running while the agent works.
- **One notice instead of many error cards.** If part of an agent's output in a turn can't be shown, the chat shows one short notice for that turn instead of an error card for every event.
- An archived or deleted run leaves the sidebar right away, also when it was removed from another window.

## Upgrade Notes
- **What the first start converts.** Each existing task agent's memory moves out of its coordinating run into its own run, with its own message history. Message histories are converted to a format that adds each new message at the end instead of rewriting the whole history. Every message, reference file and attachment link is kept, and the app looks the same as before. On large installs the first start can take a little longer. If a step can't finish, the app still starts and works, and the next start continues it. The old generated work-trace export folders are removed; the run histories themselves are unchanged.
- **Docker.** The server image is `autobyteus/autobyteus-server:1.5.6`, and `:latest` and `:beta` now point to it. If you follow the beta track with the public launcher, you can return to stable with `autobyteus-docker upgrade --all --tag latest`, because this release is newer than every 1.5.6 beta. A Docker node converts its data on the first start too, so back up its data volume first; going back to an earlier image after that is not supported.
- **`create_or_update_project` is removed.** Agents that still list it start normally without it. Select `create_project` and/or `update_project` for agents that create or change Projects.
- **Memory Sync.** A node on this version exports task agents as runs of their own. Data imported from a node that has not been updated yet shows its coordinating runs without their task agents until that node is updated and syncs again. Nothing is deleted.
- **Meaning search needs to download its model once.** Behind an HTTP proxy the download does not work yet: meaning search then shows as unavailable, and exact search still works.
- Existing MCP server settings load unchanged. Servers without credentials, and local (stdio) servers, work as before.
- Existing Tasks need no conversion for **Part of**; they simply have no parent.
