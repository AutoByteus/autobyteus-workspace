# Backend Validation Prelaunch Gate
Status: adopted execution procedure from CRR-001; no new backend launched in API-REV-002. Not retrospective proof for PID 12928 or PID 28810.

Before any later server start (not after it begins migrating):
1. Read current AppConfig/database-location/startup instructions and every selected launch wrapper. Allocate a fresh, owned, absolute temporary root; establish ownership and canonical realpath. Do not reuse production or unknown existing data.
2. Construct a dedicated child environment, not a blind ambient spread. Keep only reviewed executable/platform/login prerequisites required by the scenario; explicitly set APP_ENV=test, DB_TYPE=sqlite, DATABASE_URL=file:<owned-root>/data/db/validation.db, AUTOBYTEUS_SERVER_HOST=http://127.0.0.1:<owned-port>, AUTOBYTEUS_MEMORY_DIR=<owned-root>/data/memory. Omit/reject unrelated inherited storage/runtime overrides. If installed CLI needs the operator login, document that separate intentional external dependency; it is not authorization to use production SQL or memory. Do not print secret values or copy credentials.
3. Inspect the intended child .env/config and resolve precedence using the current source's policy without importing app/server-runtime or opening SQL. --data-dir is not SQL authority. Reject relative/ambiguous database URLs. Resolve app data, SQL path, root key `${databasePath}.secret.key`, DB -wal/-shm/-journal sidecars, memory, logs, definitions, workspace/other writable roots under the known owned root. Check existing path components/parents for symlink or other ownership escape. Fresh DB/key must not already exist; do not inspect any existing key contents. All constraints must pass before launch. Any unverifiable target stops execution.
4. Record a value-free/sanitized preflight manifest: root, canonical target paths, explicit non-secret child env values, command/cwd, chosen unused ports, ownership checks, and approval/result. Reject any target outside the owned root; no automatic correction of production paths. Bind exactly this checked environment/config/argv to spawn, with no subsequent environment mutation or wrapper fallback. Data-root freshness reduces TOCTOU risk; reject unexpected concurrent changes.
5. Only after successful preflight launch. Startup-path log comparison is defense-in-depth, NOT the first isolation check. Unexpected target → stop only owned process, preserve evidence, report incident; never infer safe startup merely from 'no pending migrations'. Readiness and query execution follow the target check.
6. Record owned PID/process tree. Cleanup only those processes/roots after preserving non-secret evidence. Never roll back/delete production data or unrelated provider state. Unknown impact requires independently supported evidence or informed disposition through Solution Designer.

Source basis: config/app-config.ts explicit DATABASE_URL precedence and AUTOBYTEUS_MEMORY_DIR; config/application-database-location.ts DB-associated key; server-runtime.ts schema/coverage/vault/app-data startup. This checklist is not a production-code change and has not itself been claimed as a newly executed regression test.
