## After you switch a run's agent runtime, the new agent is told which work journal to read first

- When you change the agent runtime of a run that already has work in it, the new agent now gets a clear pointer to what the previous agent did most recently: the name and the full path of that work journal file, and the request to read it completely, from its first line to its last, before it replies or goes on with the work. Before, the notice pointed to the file that holds nothing but the hand-over right after a switch, so the new agent often never read the earlier work and the quality of the run dropped after each switch.
- The notice still lists every work journal of the run, oldest first, for anything older. If you switch before any work was done, there is nothing to read and the notice says only where the journals are.
- The agents on Codex and on AutoByteus read the named file to its last line in our checks, also when it was long. The agent on the Claude Agent SDK, in the same checks, read the start and the end of a very long journal (about 2,400 lines) and skipped the middle, so after a switch to it the continuation may rest on part of the journal. We are following this up.
