## Evidence And Decisions
Current 2.5 Flash is the server/web blank fallback, while 3.1 Flash preview is pinned by the real live audio scenario. Old API aliases differ from visible IDs. Official [Google speech documentation](https://ai.google.dev/gemini-api/docs/generate-content/speech-generation) requires verbatim transcript parts, speech metadata for style/speaker, 3.8 voice config and ordinarily a complete WAV response; mere model-ID replacement is unsafe. Official [Google SDK releases](https://github.com/googleapis/js-genai/releases) show 2.24.0 latest stable at design time, versus v1 declared/locked locally. The built-in Gemini LLM rows are current `gemini-3.8-flash` and published `gemini-3.1-pro-preview`; [Google Flash](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash), [Pro preview](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-pro-preview) and [deprecations](https://ai.google.dev/gemini-api/docs/deprecations) do not justify an LLM catalog change now. The shared SDK still requires non-TTS regression checks. Source evidence, commands and unknowns are in canonical investigation notes.

A saved speech setting lives in the server data-dir `.env`, not SQLite. Both normal server and standalone host call `AppConfig.initialize()`. The design confines historical IDs to a one-key startup migration in that shared boundary; normal resolver/catalog/provider adapter stay current-only. Parent-process overrides cannot be durably rewritten by the app: externally supplied retired IDs fail with actionable, value-safe remediation. The existing `pnpm secrets:import` is an explicit, dry-run-and-TTY-confirmed operator workflow with an absolute isolated SQLite target; no new importer, implicit credential read, or production-vault mutation is authorized.
