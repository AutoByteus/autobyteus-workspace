### Round 15 API/E2E Round 7 classification investigation

- Investigated API/E2E Round 7's focused mixed task-delegation failure as a possible local invariant bug.
- Temporary local diagnostics showed the task-agent exact run was not forgotten/tombstoned before valid acceptance. Instead, the coordinator's automatic turn after the task-agent completion report called `accept_task(task_id="task_0001")` as the original delegator before the test sent its explicit revision instruction.
- The later explicit revision send then correctly rejected because `accept_task` had already tombstoned the task-agent run id and settlement had been scheduled.
- No source changes were retained from this investigation.
- Classification: not a local implementation defect under Round 14. This is live model/tool-choice/test setup behavior (`autoExecuteTools: true` + `tool_choice: "required"` leading the model to choose configured `accept_task`) unless product requirements change. ### Round 11 API/E2E Round 5 task-agent exact-run feedback local fix

- Investigated the remaining live mixed-task-delegation failure as a local missing invariant, not a design issue:
  - Round 5/Round 8 design already states that `target_agent_run_id` can target active/recoverable task-agent runs inside the team boundary and that `accept_task` is the terminal settlement transition.
  - The failing path rejected coordinator feedback before `accept_task` because mixed exact-run resolution depended only on the active `TaskAgentDirectory` entry, while task-agent delivery itself already had recoverable-handle support.
- Extended exact-run task-agent reachability consistently across resolution and delivery:
  - `TeamMessageRecipientResolver` now falls back to the mixed task-agent handle recovery cache for concrete task-agent run ids when the active directory entry is missing.
  - Recovery is tightly identity-validated against the current team run id, concrete task-agent run id, task id, task-agent instance id, logical member route key, template member run id, and member path before producing a task-agent resolved target.
  - Resolved recoverable targets still use the ordinary unresolved-intent -> mixed resolver -> committed-delivery path; runtime adapters remain thin.
- Preserved post-acceptance rejection semantics:
  - `TaskAgentDirectory` now records settled task-agent run tombstones and clears stale tombstones when a new starting task-agent registration reuses a run id.
  - The resolver refuses settled task-agent run ids before consulting recoverable handles, so stale/post-`accept_task` targets still reject without Team Communication projection.
- Added focused unit coverage for:
  - delivery to a recoverable task-agent exact run when the active directory entry/local map is missing;
  - rejection/no projection for a settled task-agent exact run even when a recoverable handle remains.

### Round 8 unresolved-intent / resolved-request split

  - `TeamRun.deliverInterAgentMessage(...)`, team manager/backend interfaces, AutoByteus/Codex/Claude adapters, and parent-boundary forwarding now accept/forward an intent containing only sender endpoint, target selector, content, message type, and reference metadata.
  - The intent shape has no `recipient` field and does not construct placeholder exact-run recipient participants.
- Replaced `inter-agent-message-delivery-request-builder.ts` with `inter-agent-message-delivery-intent-builder.ts`.

- Moved recipient resolution fully inside mixed delivery:
  - `TeamMessageRecipientResolver` resolves directly from `intent.target`.
  - It no longer depends on a pre-resolved `request.recipient.selector` for logical-name lookup.
  - `TeamMemberDeliveryCoordinator` creates the internal `ResolvedInterAgentMessageDeliveryRequest` only after resolver success; `recipient` exists only in that internal resolved request.
- Updated parent-boundary forwarding:
  - `normalizeMixedParentBoundaryDeliveryIntent(...)` normalizes the sender into the parent-rooted represented-subteam address and preserves the unresolved target selector for the parent boundary to resolve in its own context.
- Enforced canonical parser fields:
  - `recipient_name` and `target_agent_run_id` are the only target selector fields accepted.
  - Hidden aliases `recipient`, `recipientName`, and `targetAgentRunId` now fail validation before delivery.
- Added/updated focused coverage for:
  - unresolved intent builder output with no `recipient`, no roster lookup, and no placeholder exact-run recipient;
  - parser rejection of hidden target-selector aliases;
  - strict roster-name `recipient_name` routing when `memberName !== memberRouteKey`;
  - normal-member exact-run routing;
  - active task-agent exact-run routing;
  - settled/external exact-run rejection without communication projection;
  - parent-boundary unresolved forwarding preserving target and normalizing sender only;
  - committed Team Communication projection only after recipient input acceptance.
