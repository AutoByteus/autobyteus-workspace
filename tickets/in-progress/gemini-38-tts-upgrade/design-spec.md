## Current-State Read
The audio factory supplies the three retiring Google TTS catalog rows and one shared parameter schema. The speech tool selects the server setting through `MediaModelResolver`, creates the factory client, and copies the returned file to the requested output path. Today the 2.5 Flash ID is the blank fallback on both server and web; nonblank saved IDs override it. `GeminiAudioClient` prepends style text to the transcript, sends a string prompt and legacy voice configuration, and assumes headerless PCM for absent/PCM MIME. Those assumptions conflict with Google's 3.8 transcript/metadata/WAV contract. AppConfig persists the explicit default in the server data-dir `.env`, not SQLite. `@google/genai` v1 is shared by audio, LLM, image, and video adapters. The existing importer/test vault are already separate from production speech settings. See the source/path evidence in [investigation notes](investigation-notes.md#2026-09-24-post-approval-architecture-investigation-sr-005).

## Task Size And Architectural Risk
- `task_size`: **Large**. This is not merely two catalog records: implementation crosses shared package SDK and lockfiles, provider speech request/output contract, server startup persisted-setting transition, server/web defaults, tool schema, and executable validation across Google modalities.
- `architectural_risk`: **High**. Material external request/output contract change, SDK major upgrade with shared blast radius, and one-key persistence migration of a private `.env` are present. Provider entitlement and SDK metadata serialization remain validation uncertainties.
- Payload inventory (two new catalog rows, three removed rows, mappings/fixtures/docs) alone does **not** drive the classification. Structural surfaces above do. Escalate back as `Design Impact` if the SDK forces a public interface/owner change, migration cannot safely preserve externally overridden settings, or 3.8 provider wire behavior materially differs from the official contract; seek renewed approval only for changed intended behavior.

## Task Design Health Assessment
- Change posture: **Behavior Change** with bounded config migration and major shared dependency upgrade.
- Current design issue: **Yes, locally**. Root cause: **Legacy Or Compatibility Pressure / Local Implementation Defect**. The old Gemini TTS payload intermixes style and spoken text, assumes old voice config and treats missing MIME as PCM; the old catalog/default/mapping are coordinated in several files. This was coherent for the previous provider generation, but is wrong for 3.8.
- Refactor needed now: **Yes, narrowly**. Replace the legacy audio request/output branch and retired catalog/mappings; introduce a focused startup migration owner for historical IDs. Do not refactor unrelated media/SDK architecture or create a second Google audio adapter.
- Residual risk intentionally deferred to validation, not hidden by runtime fallback: entitlement/region for Vertex Express/project, SDK metadata serialization, and actual voice response formats. Failures are reported, not silently substituted.

## Terminology
“Retired IDs” means the three old **catalog identifiers** `gemini-3.1-flash-tts-preview`, `gemini-2.5-flash-tts`, `gemini-2.5-pro-tts`; old API aliases are not new choices. “Explicit saved selection” means that key exists in the server data-dir `.env`; a parent-process override is externally managed and cannot be durably rewritten by this app.

## Legacy Removal Policy
**No backward compatibility; remove legacy code paths.** Delete three old built-in audio registrations and their TTS runtime maps, the 2.5 fallback constants, 3.1-pinned live scenario, style-as-prompt and legacy provider voice/PCM assumptions. Historical catalog IDs may remain only in a one-time config migration module and its tests/history, not runtime catalog/resolver aliases. Keep generic PCM conversion solely if it still serves a documented, explicitly identified response format; do not use it as a default for missing MIME.

## Persisted Data / State Transition Decision
- Subject/location/volume: One optional `DEFAULT_SPEECH_GENERATION_MODEL=<catalog ID>` assignment in the server data-directory `.env` per server; contents of the owner's private file were intentionally not read. Separate secret-vault SQLite state is unaffected. AppConfig parses the file and prefers inherited `process.env`; Settings writes the file. An old explicit ID wins over fallback but no longer resolves after removal.
- Decision: **Migration Required** for explicitly saved retired catalog IDs. Direct use fails catalog resolution; discard loses an approved explicit choice; a one-key transform has low I/O but touches a secret-bearing file, so atomicity/privacy matter. Blank, current, other-provider and unknown values are not migrated. The normal resolver stays current-catalog-only.
- AC support: AC-002/003 data continuity, AC-006 explicit failure, AC-008 confidentiality.

### Migration Plan
- Current target: exactly `gemini-3.8-flash-tts`. Historical source: the three retired **catalog** IDs above; no global schema version exists. The resulting new value in the same setting is the completion marker. No SQLite or vault migration.
- Trigger/owner: inside the shared `AppConfig.initialize()` after config file loading and before initialization returns, so both `src/app.ts` and `standalone-application-host/start-standalone-application-host.ts` are covered. Add a config-owned migration function (e.g. `autobyteus-server-ts/src/config/migrations/retired-speech-model-selection.ts`); keep old IDs there only. Capture inherited `process.env.DEFAULT_SPEECH_GENERATION_MODEL` **before** dotenv loading, so external override is distinguishable. `MediaModelResolver` remains current-ID-only.
- Steps: (1) use the already parsed file value and captured inherited value without logging values; (2) if inherited override is one of the retired IDs, fail startup with a value-safe message requiring the operator to update external configuration—do not claim a durable migration of the parent environment; (3) if file value is retired, call the existing `replaceEnvironmentAssignmentFileDurably` for that one key, then verify the targeted file assignment parses as Flash; (4) AppConfig updates its `configData` entry and, only when no inherited override existed, the dotenv-loaded `process.env` entry; otherwise preserve the inherited non-retired process value; (5) leave every unrelated assignment untouched. If file has no retired value, do nothing. Unknown explicit values retain current explicit-error behavior, not a 3.8 alias. Do not call `setDurably` here: it requires fully initialized AppConfig and clobbers external process overrides.
- Safety/recovery: The existing durable writer uses same-mode temp, fsync and rename; a pre-rename error leaves source intact and startup fails. No copy of the whole secret-bearing `.env` into a tracked backup. On validation failure, startup fails with a value-safe diagnostic; operator repairs file/permissions/config through established procedures. Re-running after a successful write is a no-op. Test absent/current/retired/other-provider/unknown values, repeated startup, write failure, inherited current/retired override, file mode and preservation of unrelated bytes. No concurrent two-version deployment is assumed safe while both write the same `.env`; perform cutover with old server stopped and preserve ordinary operator rollback capability. Keep the migration module while deployed old settings may exist; retire it only after a separately evidenced fleet transition.

## Interface Shape And Concrete Guidance
- Preserve `BaseAudioClient.generateSpeech(prompt, generationConfig?, operationOptions?) → SpeechGenerationResponse.audio_urls` and server `generate_speech` input/output. No new route, schema field or public facade.
- Single speaker: nonempty prompt is a verbatim part; optional `style_instructions` becomes part speech metadata style, not transcript text; `voice_name` resolves to 3.8 `voiceConfig.voice`. Keep existing studio voice choices. Prefer SDK-typed `speechMetadata` if that is what installed v2 exposes; verify serialized `speech_metadata` on the actual request with a wire-contract test because Google's JS documentation uses snake case.
- Multi-speaker: parse nonempty prompt lines in the documented `Speaker: utterance` form, splitting only the first label separator; every line's speaker must have exactly one valid `speaker_mapping` voice, and each resulting part contains only the utterance plus metadata speaker/style. Reject malformed/unmapped/duplicate-conflicting mapping rather than speaking labels or silently dropping turns. Preserve order and allowed text punctuation. A speaker config entry is **`{ speaker, voiceConfig: { prebuiltVoiceConfig: { voiceName } } }`** inside `multiSpeakerVoiceConfig.speakerVoiceConfigs[]`; each turn part carries `speechMetadata.speaker` (wire spelling verified in installed-SDK test). Google's single-request 3.8 multi-speaker contract supports **at most two prebuilt-voice speakers**; reject more than two distinct configured/mapped speakers before the provider call. Do not infer voices from arbitrary prose or add a multi-call concatenation workflow.
- Audio: confirm returned `inlineData` is nonempty; if WAV declared or header detected, validate RIFF/WAVE structure and nonempty payload, write as WAV without another header. Wrap only explicitly declared supported PCM with validated channel/rate parameters; reject unknown/empty formats rather than emitting `.bin` as success. Output path integration remains owned by `MediaGenerationService`.
- Interface/boundary check: `generateSpeech` is singular and explicit in model instance + prompt/config; `AppConfig` one-key durable setter is singular/explicit; current model lookup identity is a catalog ID. Ambiguous selector risk **Low** once old aliases are removed. Names `GeminiAudioClient`, `MediaModelResolver`, `AppConfig` naturally describe current subjects; the proposed `retired-speech-model-selection` module describes history and must not become a normal resolver.

## Change / Refactor Sequence
1. Verify implementation-time stable Google SDK version, upgrade declaration and both lockfiles, compile/check existing Google adapter surfaces. Do not change LLM catalog IDs based only on an SDK bump.
2. Replace Google TTS catalog/mapping and server/web fallback coherently. Add startup migration and focused tests before old IDs are removed from runtime choices in a deployable build; no production server should observe a half-cut state.

## Key Tradeoffs And Risks
A strict labeled-dialogue parser limits malformed inputs but aligns with the existing tool instruction and prevents audible labels; any broader dialogue grammar would be a new contract and needs approval. A one-key startup migration changes a private file but avoids a permanent legacy runtime alias; external inherited overrides must be changed by their operator. Keeping shared SDK v2 requires a wider regression suite than a TTS-only dependency pin. Live 3.8 access in Vertex modes and exact metadata serialization remain test gates; do not assert success from documentation. A failed provider entitlement is an explicit failure/skip with remediation, not evidence that an old TTS model should be restored.
