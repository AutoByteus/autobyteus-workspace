## Problem And Desired Outcome
Projects already persist manually authored Tasks, but agents lack compact first-party management access. User requests one read-only Project list (ID/name/description) plus two Task operations: list within a Project with an optional TODO/IN_PROGRESS/DONE filter, and a combined create-or-update operation; no separate find/search tool is needed. SD-CF-008 explicitly proposes naming the combined operation create-or-update. Recommend one Task per call: omitted Task ID creates TODO, existing ID patches description/status, supplied unknown ID fails. Detailed branching remains part of the unapproved baseline (DEC-015), not a further missing high-level create capability. SD-CF-012 explicitly defers CLI/scripts/client/skill to a separate future ticket and returns to existing MCP access without scope growth. Active delivery is the three first-party native/MCP Project/Task operations plus the previously approved manual UI. The earlier hybrid exploration is historical evidence, not this ticket's deliverable or approval prerequisite (DEC-016).

This ticket provides those tools, usable by a Project Task Manager **created by the user separately**, plus the previously approved small Projects/Tasks UI updates. Existing `list_available_agents`, `delegate_task` and `send_message_to` are reused unchanged; no new Manager/team package, launch experience or delegation system is delivered here. Projects remains experimental/default-off, with the user's installation untouched.

Observable target: caller lists Projects to obtain their IDs/names/descriptions, chooses the intended Project (or uses an explicitly supplied ID), lists its Tasks (optionally TODO only), reasons about ordering/granularity/dependencies externally, creates or revises Tasks through the proposed combined create-or-update capability, reuses existing delegate_task, then explicitly marks IN_PROGRESS after successful launch and DONE after its completion decision. The tool does not launch work or infer status from runtime events. The approved manual Projects/Tasks UI remains usable and presents current fetched task data. A business Done write does not implicitly stop runtime resources, delete history or certify delegated results. The caller's Manager workflow is external to this ticket.
