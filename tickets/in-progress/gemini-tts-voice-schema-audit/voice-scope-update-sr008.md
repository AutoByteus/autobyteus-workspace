# Solution Scope Update — Only Demonstrably Working Google Speech Features (`SR-008`)

## User Direction And Current Result
The user accepts omitting dynamic voice discovery and asks to include only features we can actually make work in generated speech. The Draft [requirements](requirements-doc.md) now withdraw provider voice catalog list/search from `REQ-001/AC-001` and `SCN-001` without renumbering. The existing 30 featured voice choices remain a known subset; they are not advertised as the full Google library. This is a clear pre-approval product-scope decision, **not** final approval of the remaining proposal.

## Evidence Boundary
- **Live-proven for the configured Vertex Express key/route:** one 2026-10-02 exact `gemini-3.8-flash-tts` basic single-speaker request with the existing default voice produced a 322,538-byte adapter-validated RIFF/WAVE file. It does not establish that all 30 voices, extended/custom IDs, multi-speaker live output, or advanced styling work with that key.
- **Route-specific negative evidence:** one non-mutating `voices.list` call on the same configured Vertex Express mode returned HTTP 404. Google's [Gemini Voices API](https://ai.google.dev/api/voices) documents catalog and voice lifecycle; the [Vertex Express REST reference](https://docs.cloud.google.com/gemini-enterprise-agent-platform/reference/express-mode/api-reference) omits the Voices resource. The HTTP 404 supports caution for this route, not a claim of universal Google unavailability or a definitive `voices.create` result.
- **Documented but not live-proven here:** Google's [3.8 TTS guide](https://ai.google.dev/gemini-api/docs/speech-generation) describes Extended/catalog/custom voice IDs, per-turn styles and up-to-two-prebuilt-speaker dialogue; [Voice design](https://ai.google.dev/gemini-api/docs/voice-design) and [Voice replication](https://ai.google.dev/gemini-api/docs/voice-replication) describe creation via Voices API and additional consent requirements. Existing app code implements a 30-name enum, global style and one-call up-to-two-prebuilt-speaker mapping, but the direct current-key probe covered only one basic request. Documentation and deterministic tests are not a route-specific live success for proposed features.

## Decision Needed Before Approval
The user earlier explicitly requested **in-app voice creation**. Removing discovery does not automatically remove design/replication. However, a “verified-only on the present Vertex Express key” policy would defer voice creation, Extended/custom IDs and other unproven features until a capable mode/key is selected and successfully checked. Clarify whether the user wants that conservative deferment, or wants a separately configured AI Studio/full Vertex route to validate and enable voice creation without silently switching credentials. No remote voice creation or replication experiment is authorized by this statement alone. `DEC-001–004` in the Draft remain open; especially `DEC-002/003/004` must be resolved before final requirements approval and architecture.
