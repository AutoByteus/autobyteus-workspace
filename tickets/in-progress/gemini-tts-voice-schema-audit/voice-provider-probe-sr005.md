## Observed Result and Interpretation
- The sole provider request returned **HTTP 404 / SDK `NotFoundError`**, no voice list. This is a **Fail for voice discovery on the configured Vertex Express route/key at this test time**, not a claim that Gemini 3.8 speech generation failed: basic 3.8 Flash TTS passed previously on that route.
- The installed SDK's `voices.list` code targets `/{api_version}/voices`; its Express base is `aiplatform.googleapis.com`. Google's [Express reference](https://docs.cloud.google.com/gemini-enterprise-agent-platform/reference/express-mode/api-reference) lists no Voices API, while the [full Vertex Project Voice design guide](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/text-to-speech/voice-design) uses project/location-scoped `v1beta1` Voices endpoints. This supports the **inference** that Voices management is not exposed to this Express configuration. It does not establish global unavailability, precise entitlement cause, or whether a known Extended voice ID could synthesize through Express.
- Two earlier **local-only** harness attempts did not reach Google: importing the CommonJS and ESM builds of `repository_prisma` in one Node process produced misleading isolated-vault `CORRUPT` health. Reusing the ESM module instance matched the app and yielded READY before the one provider call. The importer itself reported READY throughout; no production-source failure is inferred.

## Requirement/Design Boundary
The current Draft `REQ-001/004/005/006` cannot promise voice list/create/manage on Vertex Express. `DEC-002` needs user choice: explicit unavailable state with a documented capable AI Studio/full Vertex Project setup, or an explicitly configured separate voice-service credential. Do not silently use the AI Studio key just because it was present in the private source/test vault. No code or final architecture decision follows from this one probe. Replication remains untested and requires genuine consent audio and explicit scoped authorization.
