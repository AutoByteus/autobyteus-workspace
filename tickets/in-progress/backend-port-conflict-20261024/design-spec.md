## Current-State Read
E-001..018 and P-001..006 in the canonical investigation establish three independent problems: missing application-lifetime ownership of native command groups, false-success leader-only termination, and generic desktop conflict handling. Desktop quit also fails to await cleanup. Existing native background managers belong to transient agent contexts; ending an agent is intentionally not the requested cleanup boundary. Existing provider-specific cleanup remains authoritative. Historical Nuxt ancestry is unknown: the native reproduction is a real defect, not proof of that incident's origin.

## Task Size And Architectural Risk
- task_size: Large. Actual implementation spans core terminal ownership/execution, native backend factory injection, two server host shutdown compositions, desktop lifecycle and main→renderer diagnostic contract/UI. This classification is not based on artifact volume.
- architectural_risk: High. Process signalling safety, shared runtime ownership, shutdown races/time budgets and IPC contract changes are material. P-005 disproves the naive local fix.
- Escalation: inability to preserve normal agent/idle lifetimes, provider-specific leakage discovered, unsafe/unverifiable group identity, required persisted ownership, or inability to meet real orderly desktop shutdown requires Solution Designer refinement before dependent implementation. Do not expand to daemon reclamation or provider rewrites.

## Intended Change
Give native command processes an explicit application lifetime, stop and verify owned groups before successful backend shutdown, await that shutdown from desktop quit/restart, and explain external port conflicts without destructive repair.

## Spine Narratives / Ownership Map
DS-001 retains current generation cancellation and readiness logic. Availability checks both required IPv4 client127.0.0.1 and bind0.0.0.0 addresses (sequential temporary binds with guaranteed close). Only EADDRINUSE enters conflict polling; other errno fails honestly. At expiry do one bounded owner lookup, not a repeated OS-command loop. Recheck after a failed launch only after its owned child has exited; a live own backend is not diagnosed as external. Guards do not claim to reserve the endpoint.

DS-002 registers ownership at command spawn, not only when a tool finishes. NativeCommandProcessScope is created once per host, passed through process provider factory → native factory → explicit AgentConfig.nativeCommandProcessScope → context → manager/executor. AgentConfig.copy retains that reference. It is not serializable initialCustomData. Core standalone consumers may own their own explicitly constructed scope; no process-global registry. An unhosted manager's local scope is its own lifecycle, not a server fallback. Hosted factories require the supplied host scope. Both start_background_process and run_bash use it; in-flight shell commands are registered before their result/adoption. Ending an agent or losing its context does not release a live group.

DS-003 freezes new native command admissions, drains owned groups early in Fastify preClose, then executes ALL existing lifecycle/provider/resource cleanup. Native drain returns a report instead of throwing in preClose; final onClose aggregates/throws incomplete cleanup after other cleanup attempts. Startup-failure cleanup also closes the scope even if app/hooks were not fully created. Studio and standalone use the same small host-shutdown integration helper, not two versions of the policy. Direct backend SIGTERM and the Windows child IPC request enter the same ServerProcessShutdown owner; it exits nonzero on incomplete cleanup. The old local signal-only closure is removed, not left as a second owner. Desktop observes termination, not a successful kill call.

DS-004 serializes only plain diagnostic data. All snapshots (including getStatus) carry the same current value. Restart/starting/running clears previous details. Stale async diagnosis cannot overwrite a newer generation. UI does not parse error prose to choose recovery.

## Bounded Local Spines / Concrete Termination Contract
Parent owner: NativeCommandProcessScope; states open → closing → closed, one shared close promise. Acquire an admission before spawn; register resulting ChildProcess/target identity before releasing the reservation. Closing rejects new admissions, includes already admitted in-flight starts, and has a total3s default budget (not3s per command). Do not allow late adoption to create an untracked survivor after closing.

ProcessGroupObserver remains the OS mechanism. Replace its unsafe raw-pid-only stop contract with an owned identity handle and structured outcome: stopped/already-exited/unconfirmed, reason and surviving known identities. Target includes host or exact WSL distro; equal numeric PIDs in different targets are not interchangeable. At spawn/adoption capture available birth identity (POSIX ps start-time identity with fixed locale; WSL equivalent) and process-group membership; retain live anchors as leader exits. A running ChildProcess handle is an additional ownership anchor. Before each signal, confirm live matching owned anchor(s) and current group; never signal a stale PID/group solely because its old number is present. An empty successful group observation means gone; an observation failure is unknown. Retire records only on confirmed absence, not leader exit alone. If all anchors are lost and identity cannot be re-established, fail closed rather than reclaim a numeric group.

Take a fresh group snapshot before TERM, so a child that outlives the leader remains a known anchor (P-005). Signal verified group, allow500ms graceful period, re-observe group members even if leader exited, then KILL remaining verified group and poll to deadline. Batch observations by execution target and drain groups concurrently; enforce bounded inspection subprocess timeouts (≤500ms within remaining budget), output limits and signal failures. Keep error detail, never translate inspection denial into empty. Same mechanism serves explicit stop_background_process and timeout/abort; keep their external tool semantics except that failed/unconfirmed stop is no longer falsely successful. Background output records may remain per-agent; process ownership is retained by scope independently. No per-process port scan, shell interpolation of command text, or global process-name kill.

Native stop cannot guarantee hostile daemon escape or eliminate all OS TOCTOU. Unsupported identity inspection must give a precise incomplete result, not silently downgrade to arbitrary kill. Existing WSL identity marker must be registered as soon as parsed; a close during marker acquisition cannot report clean success without confirmed child/group exit. These are required failure tests.

## Desktop Shutdown Contract
Extract a small cached shutdown coordinator under electron/application. In will-quit, preventDefault until stop settles; subsequent quit attempts reuse it. Broadcast app-quitting once; after success mark complete and resume app.quit once without recursion. Cache a Promise, not only a boolean that lets later callers return before shutdown finishes. Ordinary closing the last macOS window is still not app quit.

BaseServerManager.stopServer keeps managed-child-only authority. Use20s graceful backend budget then owned-child force termination and2s confirmation budget; no unbounded close wait. Child exit and pipe close are distinct; inherited pipe handles must not masquerade as a live backend. Nonzero cleanup exit, forced fallback or unconfirmed exit is an explicit shutdown failure, not clean restart success; StatusManager must not launch a replacement within that failed restart attempt. A later explicit retry can proceed with fresh port diagnosis. Windows uses the concrete managed-child IPC entry below BEFORE any tree-force fallback; taskkill without /f is removed as the purported graceful entry. No advisory port owner is signalled.

Application stop attempts backend AND browser-runtime teardown even when one fails, aggregates failures and flushes logs.30s total desktop quit ceiling leaves bounded completion headroom; on failure/ceiling record incomplete shutdown and use nonzero exit rather than claim clean success. No recursive timer calling app.quit. Under the normal verified path, quit only follows cleanup. Forced OS kill is outside R1.

Explicit AppUpdater install continuation must await the same application stop before invoking existing quitAndInstall, because the installed updater may start installation before emitting quit. Add a prepare-for-install callback at its composition boundary; failed preparation becomes existing install error, no installation. This is lifecycle preservation only: tests use a mocked updater, no download/install. Normal auto-install-on-quit stays behind final quit; do not call app.exit(0) to bypass it. Preserve existing isolated updater-disabled behavior.

## Windows Managed-Child Shutdown Entry / Startup Cancellation (AR-001)
**Transport and association.** Keep the existing Node-mode child spawn, not HTTP, public port, process-name lookup or a new supervisor. WindowsServerManager changes stdio to ['ignore','pipe','pipe','ipc']; its existing env sets ELECTRON_RUN_AS_NODE=1. Immediately attach ManagedBackendShutdownClient to that captured ChildProcess, before async readiness waits. Its lifetime is that child, not whichever PID later occupies the port. Parent listens to that child's message/error/disconnect/exit events; no response from a different launch/generation is accepted. macOS/Linux keep SIGTERM as their external trigger; both triggers use the same backend shutdown owner. No forced SIGTERM emulation on Windows.

**Small wire contract.** JSON-serializable strings only: `autobyteus.embedded-server.shutdown.v1:ready`, `:request`, `:complete`, `:failed` (the latter three use the same full prefix). No PID, command, handle transfer, arbitrary object dispatch or serialized error. Adapters match exact literals and ignore other messages. One stop promise per captured child, one request, no retry queue or correlation field: the dedicated channel and single child lifetime are the identity. Keep protocol literals in the two transport endpoint modules and pair them with a cross-boundary contract test, following the existing separately packaged platform-fatal transport convention; do not introduce a general contracts package for four strings or duplicate domain state models.

**Backend owner and initialization.** Add `ServerProcessShutdown` in server shutdown code. Construct/register it at the FIRST synchronous step of startConfiguredServer, before asynchronous process prerequisites or Studio creation; it installs process message and POSIX signal adapters, then advertises :ready only when the request latch is active. This is control readiness, NOT HTTP readiness. Before that point the parent waits on the same20s stop deadline; an import/config failure exits nonzero and is not mislabeled as graceful cleanup. No guarantee is made for a hung pre-runtime import.

The owner has a single shutdown request latch and single completion promise. During startup it marks cancellation immediately but does not close resources concurrently with initialization. The startup path checks cancellation before each subsequent asynchronous initialization/listen/recovery/background-task stage and after the active stage settles. A control-cancellation sentinel is handled separately from startup fatal errors (never wrapped into an HTTP initialization failure). A startup-settled barrier resolves in finally, including errors; it does not wait on the shutdown promise (no circular wait). The shutdown promise waits that barrier, then invokes the latest registered cleanup authority once. Before Studio ownership transfer this is the existing prerequisite unwind; after successful buildStudioServer transfer it is app.close, including native scope preClose and the remaining host resources. Transfer cleanup authority before the next cancellation checkpoint; do not clear prerequisite ownership flags without registering the replacement. Partial Studio construction continues to unwind through its existing failure cleanup plus the scope closure already required by D1. Cancellation during prepare/listen/recover waits that active stage, closes the fully constructed app, and never advances to the next stage. If an initializer hangs past the parent deadline, outcome is unconfirmed/force fallback, not success.

After normal startup settles the same request directly invokes app.close. Repeated SIGINT/SIGTERM/request events reuse the single completion. Standalone host close still uses its public host owner/native-scope integration; no desktop IPC is added to unrelated standalone launch modes. Direct non-IPC CLI startup has only signal adapters and no ready message.

**Completion and budgets.** After all cleanup attempts, backend emits :complete only for confirmed successful cleanup, or :failed for aggregate failure, then exits0 or1 respectively. Bound the process.send flush callback to250ms; failed/unconfirmed flush exits1 rather than falsely acknowledging success. Native3s drain remains inside the20s graceful child-stop window. The parent send callback means transport enqueue only, never cleanup. Successful Windows stop requires both :complete AND actual child exit0 within the20s window; account for result/exit event ordering and ignore inherited stdout/stderr close delays. :failed, nonzero exit, disconnect/missing result, invalid protocol or a timeout is incomplete, never clean success.

At the20s graceful deadline, if the captured backend is still alive, invoke taskkill /pid <owned child pid> /f /t with bounded subprocess lifetime and allow at most2s additional exit confirmation. Check captured child state immediately before force action and preserve existing ownership protections; never chase a reused numeric PID or diagnostic listener. A child already exited is never signalled again. Force/error remains a failed stop even if the Windows tree exits; it does NOT prove WSL command groups drained. No new backend is launched in that failed restart attempt. Future user retry rechecks fresh port state. On app quit, existing D2 aggregate/nonzero outcome and30s ceiling apply. No-PID/spawn-error and already-exited cases report what was established; do not erase an unconfirmed live child reference to manufacture stopped state.

**Desktop startup cancellation.** stopServer first cancels the pending startup generation, independently of the child's capability readiness; no-child/pre-spawn cancellation returns without a request or later launch. If a child already exists, stop retains its control client even though HTTP readiness is cancelled. If :ready was already received send immediately; otherwise latch stop intent and send once on :ready within the ORIGINAL20s deadline. A ready/response from a cancelled generation may finish that child's stop but cannot emit RUNNING or alter a newer startup snapshot. Cache stop through concurrent quit/restart calls. Missing IPC capability is not a legacy compatibility fallback: fail honestly, then bounded owned-child force fallback if necessary.

**Tests and evidence boundary.** P-006 proves ready/request/completion/exit signalling with real Node spawn+IPC and both success/failure on macOS, NOT cleanup implementation or Windows certification. Tests must exercise the real server entry/close and Windows manager transport contract (platform force action mocked on macOS), requests before readiness/during prereqs/build/listen/recover, duplicate request/signal, failed ready/send/flush/disconnect, complete-without-exit and exit-without-complete, stale child messages, nonzero cleanup and force ordering. Changed-build Electron Node-mode IPC compatibility is a downstream packaging test; task-local Electron binary was absent during design and the installed app was not used. No live Windows certification is demanded or claimed.

## Diagnostic Interface / UI
Extend shared ServerStatusSnapshot with optional diagnostic union: {kind:'port-conflict', port, owners: [{pid, executable?}], inspection:'available'|'unavailable', observedAt} and {kind:'shutdown-incomplete', message}. Unknown startup errors use existing message without diagnostic. Own type in types/serverStatus.ts; no duplicate renderer representation. PortConflictError holds the typed data for main-process transport; generic text stays for logs.

Port inspector is advisory/read-only: execFile lsof -nP -iTCP:<validated integer> -sTCP:LISTEN -Fpc on macOS/Linux,1000ms deadline/32KiB cap, de-duplicate valid PID/executable records, cap displayed list and string length, strip control characters. No full arguments or secrets. Unsupported OS, missing binary, permission denial, malformed/empty/racing output returns unavailable and safe guidance; do not add Windows PowerShell machinery absent need. The bind result, not inspector success, establishes conflict. Current identity is a snapshot, never a kill recommendation by number alone.

ServerLoading shows port and available executable/PID, explains Restart controls its managed backend and cannot stop another application's listener, asks user to verify and stop/reconfigure that application then retry, and states resetting server data will not free a port. Do not offer reset in conflict branch; preserve generic recovery branch. Accessible text, wrapping long names, escaped interpolation, English and zh-CN manual catalog keys. Keep technical details optional but actionable diagnosis always visible. No automatic port switch, shell command, or destructive action.
