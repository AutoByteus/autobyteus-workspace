# Requirements Doc

## Status (`Draft`/`Design-ready`/`Refined`)

Refined and user-approved; SR-010 technical design correction ready for renewed architecture review (2026-07-31). SR-004 remains the implemented lineage/context/startup baseline, while the approved SR-006/SR-009 behavior removes fixed episode/fact limits, installs the exact natural system prompt and history-only operation payload, and preserves canonical user turns. SR-010 does not change that approved intent: it completes the actual accepted-publication path, assigns the changed prompt contract audit value `2` to new compactions while directly reading existing current-schema value-`1` records, restores message-only constituent provenance, and refreshes all “current” evidence to the implemented SR-004 worktree. The Memory Compactor chooses the natural number of episodes and facts needed for reliable continuation. This ticket prescribes neither item counts nor a ticket-specific output-token ceiling and does not change compactor launch configuration.

## Goal / Problem Statement

Define and then implement a unified, evidence-grounded memory contract in which:

- raw traces remain original runtime activity evidence;
- work evidence is the earliest memory-ready view, resolved from referenced authoritative raw records rather than persisted as copied content;
- every successful compaction retains explicit direct lineage to the preceding successful compaction whose output influenced it and to newly selected original work;
- WorkingContext and its persisted snapshot represent what the LLM currently sees/remembers;
- recurrent compaction consumes the current compaction output plus newly selected settled activity and produces one quality-first complete replacement output whose episode and fact counts are chosen naturally by the LLM;
- the compactable logical WorkingContext prefix—including the existing compacted-memory user region when present—is supplied to the compactor as one naturally ordered conversation history that omits private reasoning;
- native compaction and generated Work Evidence reuse one core-owned, deterministic readable-tool/text presentation policy for redaction, serialization, and explicit head/tail omission while retaining separate sources, envelopes, and consumer bounds;
- Event Monitor projection remains an active-raw-activity view rather than a memory/context view; and
- cross-runtime source identity and higher-memory provenance remain truthful.

The detailed intended behavior is normative in `memory-context-and-lineage-contract.md`, `use-case-data-flow-spine-map.md` makes every use case traceable through its complete production or approved target-production path, and `memory-compactor-prompt-content-contract.md` is the exact wording authority for the two LLM-facing prompts. This stage establishes the requirements basis; implementation design begins after approval of those normative artifacts and this document.

This is a bounded change to native AutoByteus structured memory compaction, compactor conversation-history rendering, shared readable-tool/text presentation used by generated Work Evidence, lineage lookup, canonical `WorkingContext` finalization, snapshot persistence/restore, and one startup app-data reset. It is not a general memory-evolution or external-runtime compaction project.

### Explicitly unchanged

- Raw trace records remain original user/assistant/tool/runtime activities; their IDs and content are not rewritten into summaries.
- Successful compaction may move newly selected natural raw records from active storage to archive exactly as today; prior-memory ancestry is never re-archived as though newly selected.
- Event Monitor continues to read and page active raw traces only.
- Readable server work-trace Markdown remains a separate generated presentation artifact and is not read as the native compactor input. Its source enumeration, timestamps, Markdown/file/manifest contract, reasoning omission, and generated-artifact ownership remain; only visible-value serialization/redaction and oversized-field presentation move to the shared core policy, replacing silent prefix-only loss with explicit head/tail omission.
- Storage-only external runtimes continue recording normalized raw activity and provider/session boundaries; this ticket does not add AutoByteus episodic/semantic compaction to them.
- There is no separate tool-result condenser: settled tool-call/result groups continue to be rendered directly into normal compaction input, while live/incomplete groups remain protected. Each selected group appears as one `Tool` block with `name`, `status`, `arguments`, and `result` or `error`; rendering changes from whole-item prefix-only clamping to explicit bounded variable-field head/tail omission.
- A one-time app-data reset intentionally discards pre-lineage episodic/semantic rows, the pre-v5 WorkingContext snapshot, and the obsolete compacted-memory manifest. Raw traces and raw-trace manifests remain untouched. No current runtime reader recognizes or projects the removed derived state.
- Current runner/parser failure and retry behavior remains: no candidate output or lineage record is published, the lineage head remains unchanged, and the same pending `compactionId` is retried on the next normal request.

## Recommendations

- Adopt the complete foundation contract without introducing a raw-memory persisted alias.
- Use a recurrent compaction lineage chain with direct `previousCompactionId`/raw-trace-archive-file inputs, cycle-safe traversal, and rebuildable transitive closures.
- Use one reference-only `CompactionLineageRecord` per success: existing `compactionId` + optional `previousCompactionId` + run-relative native-compaction archive `file_name` + produced episode/semantic IDs.
- Let the model choose the natural number of episodes and facts needed for reliable continuation; keep unrelated phases distinct and remove chatter/repetition/obsolete state without prescribing item counts or a ticket-specific token ceiling.
- Record already-known input/output IDs automatically; retain prompt/selection policy versions and optional integrity hashes, but do not duplicate rendered task or evidence content and do not ask the LLM for citations or storage IDs.
- Preserve the implemented run-scoped resolver and extend coverage so natural-count and mixed prompt-version membership reports direct inputs and recursive roots truthfully.
- Make the output listed by the lineage head a required recurrent compactor seed, append only a successful new record whose `previousCompactionId` matches that head, and finalize its natural memory/current-user composition inside WorkingContext before snapshot/render.
- Keep Event Monitor active-raw only and keep work-evidence/archive access separate.
- Preserve the implemented required startup reset/current-only restore boundary unchanged.
- Preserve the reachable current pre-write failure behavior: a compactor-runner failure or invalid compactor response leaves baseline context and storage unchanged, and the next normal request retries the same pending in-memory operation.
- Render the planner-selected recurrent WorkingContext prefix as one natural `<conversation_history>` block: projected M(n-1) in its model-visible user-role position followed by selected R(n), with reasoning/backend metadata omitted and each settled call/result represented as a straightforward `Tool` block containing `name`, `status`, `arguments`, and `result` or `error`.
- Reuse the implemented shared readable presentation core unchanged. Keep WorkingContext planning/XML prompt construction and raw historical replay/timestamped Markdown generation in their current authoritative subsystems.

## In-Scope Use Cases

All detailed use cases UC-001 through UC-027 in `memory-context-and-lineage-contract.md` are in scope as the design basis. They cover:

- runtime activity capture and active-only Event Monitor projection;
- reference-resolved work-evidence/origin access, natural reasoning-free compactor rendering, and generated Work Evidence rendering through separate source-owned adapters over one shared readable-tool/text presentation core;
- no-compaction, immediate-compaction, deferred-tool, new-user, multimodal, and repeated-compaction request paths;
- snapshot persistence, normal resume, one-time pre-runtime data reset, provider rendering, and external runtimes;
- recurrent quality-first complete replacement outputs with LLM-decided natural episode/fact counts and direct/recursive current-format origin-time lineage;
- reachable pre-write compaction failure/retry and active-page cursor expiry.

## Out Of Scope

- Work-evidence chunking and intra-file localization within one work-evidence file.
- Default per-token/per-sentence/raw-row citations for every episode.
- Fine LLM-selected evidence labels/citations; the selected complete compaction input is the only sourcing granularity in this ticket.
- Changes to generated Work Evidence source enumeration, timestamp/order semantics, Markdown filename/manifest contract, or its improvement-flow caller. SR-004 already delivered the shared explicit head/tail omission policy; SR-010 makes no Work Evidence change.
- A new frontend provenance/origin screen; this ticket supplies the run-scoped backend/core resolver only.
- AutoByteus episodic/semantic compaction or WorkingContext snapshots for storage-only external runtimes.
- A separate tool-result condenser or second LLM summarization pass for tool output.
- Cross-run extraction or one compaction combining independent prior-compaction outputs from multiple runs; the recurrent input is exactly one preceding successful run-local compaction output plus one newly selected run-local natural prefix.
- Separate fact-level correction APIs, invalidation/deletion/redaction tombstones, and reverse-impact traversal. The compactor may consolidate changed understanding, and previous-output projection supersession is part of the approved recurrent behavior.
- Successful compaction with an empty durable-memory projection; the current structured parser requires a non-empty episode.
- Interrupted filesystem publication, crash recovery, staged-file journals, and retry deduplication for partially written compaction state; no supported operational path was established.
- Replacing Event Monitor with a WorkingContext view.
- Adding archived history to Event Monitor paging.
- Persisting provider-private chain-of-thought or unnormalized transport envelopes. Provider-required reasoning may remain in WorkingContext/provider history, but it is excluded from the compactor's work-evidence view.
- Duplicating raw-message, prior-memory, output-memory, tool/media, or rendered-prompt content inside lineage records.
