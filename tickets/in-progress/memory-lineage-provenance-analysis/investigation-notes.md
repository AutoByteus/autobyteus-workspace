## Request Context

The user asks how compaction should transform raw traces/work evidence into episodic and semantic memory while retaining explicit source and time provenance across runtimes. The user specifically asks exactly who creates a supporting pointer, whether the LLM needs internal storage metadata, and whether detailed per-entry citations during large compaction would impose excessive work. The agreed direction is that application code automatically relates each successful `compactionId` to its optional prior producing compaction, the completed raw-trace archive file containing exactly the selected records, and produced episode/semantic IDs; fine LLM citations, work-evidence chunking, and localization are outside this ticket. The user then questioned consecutive compacted-memory/current-user turns, preferred natural composition before provider rendering, and distinguished the Event Monitor's activity purpose from current model context. The current conclusion is: raw traces remain the authoritative original activity/content; work evidence is a read view of referenced authoritative raw records, not copied content; finalized `WorkingContext` and `working_context_snapshot.json` represent what the model currently sees/resumes; Event Monitor remains active-raw only; and no compacted-memory row is inserted into raw traces. On 2026-07-22 the user authorized formal ticket work and requested a detailed foundation contract covering every use case. On 2026-07-27 the user requested an explicit previous-versus-target implementation statement. On 2026-07-29 the user directed recurrent replacement: `M(n) = compact(M(n-1) + R(n))`, only M(n) remains current, and older successful compaction outputs remain lineage history. The user then rejected duplicated evidence/prompt content and artificial locator or generation/activity identities. After seeing `Assistant work notes` in the proposed compactor input, the user asked why it exists and directed omission of separate reasoning. The user then requested one XML-style outer boundary, but corrected the first proposal because separating “current memory to revise” from work evidence exposed application mechanics. The final direction is that compaction should look like compacting the logical conversation context sent to the working LLM: the planner includes the projected compacted-memory user region plus selected later units as one ordered prefix, and the renderer encloses that natural User/Assistant/Tool transcript in one `<conversation_history>` boundary. The user clarified that both native compaction and generated Work Evidence should use one general core `CondensedToolCallRenderer`. Source adapters own selection and call/result correlation; the renderer accepts only `name`, `arguments`, a discriminated `result`, `error`, or `no_outcome(status)`, and the per-value bound, then returns only the condensed body. Normal Work Evidence has a correlated terminal outcome; if no terminal record genuinely exists, the same renderer preserves the truthful status and emits `result: not available`. The consumers do not share source selection, timestamps, envelopes, files, or orchestration. Internal metadata alone preserves exact prior-memory origin versus R(n) raw-ref ownership. On 2026-07-30 the user rejected all runtime historical-format support: pre-lineage episode/semantic rows, WorkingContext snapshots, and compacted-memory manifests are explicitly disposable and removed by one required startup app-data migration; raw traces/manifests remain. The requirements and foundation contract now define seven exact deliverables.

## Findings From Code / Docs / Data / Logs

Complete synthesis is in `provenance-methodology-analysis.md`.

Key conclusions:

1. Direct artifact/activity lineage must be persisted during compaction, not reconstructed later.
2. Raw leaf IDs already exist, but current episode/semantic models lose them.
3. Current planner recognizes and excludes synthetic memory even though it causally influenced subsequent activity. The target includes the compacted-memory message-local constituent in the natural prefix, while `MemoryManager` separately captures the current lineage tail outside the strategy. That unchanged baseline maps to `previousCompactionId`; absent/empty lineage means no current memory and a null predecessor.
4. The target recurrence is `M(n) = compact(M(n-1) + R(n))`; output is one complete bounded successor, not a delta.
5. Only the newest successful compaction output bundle is current; older outputs remain immutable/inactive history.
6. One `CompactionLineageRecord` stores only the existing successful `compactionId`, optional `previousCompactionId`, one completed raw-trace archive file's existing run-relative `file_name`, and produced episode/semantic IDs—not a parallel activity/generation ID, raw membership/content, fabricated segment ID, internal boundary key, rendered prompt, or copied transitive closure. Success requires non-empty newly selected raw-backed R(n); M(n-1) alone is not eligible and is never re-archived.
7. Recursive origin accepts run/member scope plus explicit artifact kind and ID, distinguishes direct inputs from ultimate raw roots, uses cycle protection/deduplication, and may use rebuildable indexes without changing authority.
8. Unknown typed artifact IDs return `not_found`; a missing/inconsistent relation inside a referenced current-format chain is an integrity error. No resolver reads discarded row files.
9. The directly referenced raw-trace archive file's source interval, recursive root interval, derivation time, and lineage append/derivation ordering are distinct.
10. One through three episodes and at most twenty accepted semantic facts share one direct recurrent-input pointer; detailed localization/fine citations remain outside scope.
11. The strategy returns an IDless proposal containing selected new raw IDs, retained messages, normalized content, and execution metadata; it carries no prior compaction or output identity. `MemoryManager` reuses the pending `compactionId`, validates the separately captured baseline lineage tail, assigns episode/semantic IDs, constructs/validates the accepted candidate, and maps the baseline head to `previousCompactionId`.
12. Current compacted-memory/current-user adjacency is not a safe provider-neutral assumption; WorkingContext finalization owns natural composition and typed constituent provenance.
13. Raw IDs/content remain immutable across archive movement, and prior-memory ancestry is never re-archived as new raw activity.
14. Derived compaction outputs do not belong in raw traces; Event Monitor remains active-activity only.
15. Runner/parser failure leaves the lineage tail and baseline installed/snapshotted WorkingContext unchanged while retaining the pending `compactionId`; no staged publication journal is introduced.
16. Valid schema-v5 snapshot remains normal resume authority for finalized messages, media/tool structures, and message-local constituent ranges only. It contains no compaction/output/current-state identity. Separately, absent/empty lineage means no current compacted memory; otherwise its last valid record lists the exact current output IDs. One required startup app-data migration deletes pre-lineage episodic/semantic JSONL, WorkingContext snapshots, and compacted-memory manifests while preserving raw traces/manifests. Normal runtime contains no historical decoder or fallback.
17. After one thousand compactions, WorkingContext contains only bounded M1000; durable older outputs/provenance may grow separately.
18. `Assistant work notes` is a current compaction-prompt formatting artifact over private `reasoning_content`, not work evidence. Target rendering consumes one planner-selected logical WorkingContext prefix containing projected M(n-1) plus R(n), preserves natural User/Assistant/Tool order inside exactly one `<conversation_history>` boundary, and adds no separate memory/evidence labels or synthetic timestamps. Each settled call/outcome becomes one Tool block with `name`, `status`, `arguments`, and `result` or `error`; no `Assistant tool call` label or call ID is rendered.
19. Generated Work Evidence already has the desired combined Tool-body grammar but silently prefix-slices cleaned values at 20,000 characters; native compaction independently prefix-clamps whole rendered lines near 2,000 characters. The correct refactor shares only deterministic visible-value serialization/redaction, tight Tool-body rendering, and configurable explicit head/tail omission in `autobyteus-ts`; WorkingContext and raw historical replay remain separate source authorities with separate envelopes and bounds.
20. Normal accepted publication has one order: archive R(n), persist output rows, append the validated successful lineage record as the new current head, install finalized context, persist message-only v5, then clear pending state. Strategy/LLM cannot assign produced IDs or publish any of those artifacts.
21. `compaction_lineage.jsonl` is the only persisted compaction-history/current-state authority: successful records only, absent/empty means no current compaction, and the last valid record is current. Appending requires a unique `compactionId` and `previousCompactionId` equal to the prior tail. No `compaction_state.json`, snapshot-level output IDs, replacement manifest, or activation field is added.
22. The reset migration, migration runner, and `startConfiguredServer` have separate responsibilities. The reset returns `FAILED` for any discovery/deletion failure; the runner persists all attempted required results and throws after detecting any non-startable status; the real caller logs and rethrows before bootstrap/build/listen. Existing `SUCCEEDED` and `SUCCEEDED_WITH_WARNINGS` remain startable.

## Constraints / Dependencies / Compatibility Facts

- Raw trace file paths and `active` source labels are not stable logical identities.
- The active file has mutable membership; completed archived original rows remain historical evidence. Neither active nor archive raw rows are current-context snapshots.
- Raw trace `seq` is per turn, not a run-global order.
- Work trace summary hash covers visible/redacted rendered content and deliberately excludes separate reasoning; it is not a complete raw-corpus fingerprint or evidence-selection record.
- Current work trace files are overwritten in place and can no longer reproduce an old input snapshot by path alone.
- Generated Work Evidence Markdown is not a native compaction input. Its reasoning omission and combined `tool:` body inform the contract, but native compaction renders planner-selected WorkingContext without raw timestamps or the file/manifest wrapper. Both paths may reuse the core visible-value/Tool-body/head-tail capability with different bounds.
- Current core compaction applies a default 2,000-character bound to each whole rendered line and exposes `reasoning_content` as `Assistant work notes`; both are intentional target changes, while provider-required reasoning may remain in WorkingContext.
- Cross-runtime normalization must not erase run/runtime/provider context needed for audit.
- Provenance must not force retention of provider-private reasoning or transport envelopes.
- Provider transport behavior is not uniform: current Anthropic combines adjacent turns, current tested OpenAI/DeepSeek/Grok endpoints accept them, Gemini guidance expects alternation, and Mistral templates may reject non-alternation.
- Multiple successful provider probes do not make adjacent-user transport a stable cross-provider contract.
- Canonical `WorkingContext` finalization, not provider rendering, owns memory/current-request semantic combination.
- Active membership may change after originals are archived, but original raw event IDs/content remain unchanged and no derived compacted-memory row is labeled as observed evidence.
- Current compaction persists memory/archive/active/snapshot through separate writes. Target appends a successful lineage record only after referenced outputs exist, making the append position current, but no supported crash premise justifies a new journal in this ticket.
- Current snapshot bootstrap calls the semantic schema gate before restore. Target removes that sequencing, the gate, global manifest authority, and every old-schema restore branch. Deletion happens only in the startup migration before runtime.
- A compacted-memory constituent is message-local structure only: `kind` plus character range inside a finalized user message. Projector/finalizer/serializer/planner preserve that boundary without compaction/output IDs. `MemoryManager` alone reads the lineage baseline and maps its tail to `previousCompactionId`; the current-output loader alone resolves the tail's output IDs.
