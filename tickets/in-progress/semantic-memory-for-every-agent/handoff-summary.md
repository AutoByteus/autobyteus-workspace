## Delivery Summary

- Delivered scope:
  - **Semantic memory is on for every agent, with no switch.** Every agent run in every runtime (AutoByteus, Claude, Codex, Grok, DeepSeek harness, Antigravity) and every run kind (standalone, delegated, team member, org member, application-owned, internal) gets its own folder `<memory>/semantic/<definition folder name>/` and an instructions section naming it. The `semanticMemoryEnabled` definition field, its GraphQL field and inputs, the personal setting, the form checkbox and every enabled-check are gone. A stored `semanticMemoryEnabled` in an `agent-config.json` or `personal-settings.json` is ignored on read and absent after the next save; nothing is rewritten or migrated. The agent detail page shows the folder path for every agent (`semanticMemoryPath` is now non-null).
  - **A global semantic memory.** `<memory>/semantic-global/`, shared by every agent on the node in every Project, is created when missing at each run start. Every run's instructions carry a Global Semantic Memory section (exact text in DEC-013) right after its own. Every agent may read and write it; the system writes nothing into it. Codex runs get both folders as `writable_roots`, Claude runs as additional directories; DeepSeek harness writes to either ask an escalation.
  - **The Memory page is organized by owner** (Global · Agents · Agent Teams · Agent Orgs, opening on Agents, with cards and no list filter). An agent's page has Episodic memory (its runs from every place it works, with a run filter, from its episodic catalog: `listAgentEpisodes`) and Semantic memory (its folder). Team and org pages list their Members (each opens its own page) and Runs. A shared agent opens the same page from everywhere; internal agents stay hidden while "Show internal agents" is off.
  - **The folder view is read-only and enforced by the node.** It is the Skills page's explorer and tabbed viewer over a `semantic_memory` workspace that is `readOnly` (every write, create, rename, move, delete and upload is refused `WORKSPACE_READ_ONLY`), does not follow symbolic links (a link is listed, never entered or opened: `WORKSPACE_LINK_NOT_OPENED`), is never listed by `workspaces` and can never be a run's workspace (`WORKSPACE_NOT_RUNNABLE`). It never creates a folder; an empty and a missing folder show their own message; an imported source shows "semantic memory is not part of synced memory".
  - **One folder-name rule for long IDs (DEC-016).** `encodeURIComponent(id)` up to 200 bytes; otherwise its first 120 bytes, `#` and 16 hex characters of the ID's SHA-256. The rule is owned by the memory layout and shared by `semantic/`, `episodic/` and the Memory page's lookup. An application-bundled team-local agent's ID (up to 439 encoded bytes) used to fail its run start with `ENAMETOOLONG`.
  - **A folder that cannot be prepared never fails a run (DEC-015).** The run starts without that section and the log names the agent and the reason (`SEMANTIC_MEMORY_PREPARE_FAILED { definitionId, folder, reason }`).
  - **GraphQL is a clean cut (REQ-009).** `listAgentRunsWithMemory` is replaced by `listAgentEpisodes`; `agentSemanticMemoryFolder`, `globalSemanticMemoryFolder` and `listMemoryGroupMembers` are new. The app and the node ship together.

## Residual Risks For The User

- R-1 (the app and the node ship together, REQ-009): the data behind the agent pages and the Memory page changed shape. An older app with a newer node, or the reverse, can fail to load those pages. `release-notes.md` says so under "What you need to do".
- R-2 (CF-13): an agent ID of 201 to 255 encoded bytes used to get a full-name folder and now gets the shortened name, so its old folder is not found; its files are not touched. The founder's node has none (`IMP-22`: `semantic/` 4 folders, the longest 56 bytes; `episodic/` 125, the longest 117). Release notes say how to move the files.
- R-3 (CF-11): a shortened catalog folder whose agent's runs were all removed while the server was stopped keeps its last `catalog.md` (its name cannot be decoded). Documented in `agent_episodic_catalog.md`.
- R-4 (DEC-006): until a personal-settings record that still holds `semanticMemoryEnabled` is next written, each server start logs `PERSONAL_SETTINGS_ENTRY_SKIPPED … semanticMemoryEnabled` (two records on the founder's node). The record is never rewritten just for this.
- R-5 (DEC-001, DEC-007): a native AutoByteus agent whose definition lists no file tool is told the folder but cannot use it until a file tool is added; every agent's instructions grow by about 130 words (part of the stable instructions, so prompt caching keeps them).
- R-6 (not tested): Grok, DeepSeek harness and Antigravity live (the same prompt composer, proven by unit tests, scripted AGY and the Grok replay); macOS signing and notarization, x64, Linux and Windows packaging (the release runner); a fresh-clone build of the final merged state (the clone of `42c2f5189b` passed; what came after is the base's own commits, merged twice and validated by their tickets, a demo fixture, tests, an icon and a comment; both typechecks, `codegen:check` and the web guards pass on the final state, and RELEASE.md says delivery audits and does not redo clean-clone builds).
- R-7: the host that ran these suites is out of memory (see above): the E2E files that start servers can fail with an Antigravity discovery timeout until `fseventsd` is restarted or the machine rebooted. The whole server E2E suite was not rerun on the merged state (RELEASE.md: delivery audits; API/E2E ran it in round 2).
- R-8: SM-12 makes its unwritable folder with `chmod`, which does not bind a root process; the default suite skips it (FU-006). The IC file runs its Codex turns to completion (TN-02).
